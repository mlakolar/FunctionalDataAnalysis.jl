Regression

The package fits Gaussian functional regression models by two routes. FPC regression has no smoothing parameter: β is expanded in leading FPCs. PenalizedFunctionalRegression expands β in a spline basis and selects its smoothing parameters by REML (default) or GCV through PenalizedLeastSquares. Concurrent regression records the bandwidths it uses on the fit.

All estimators follow the StatsAPI interface: fit, predict, coef, fitted, and, where the model defines them, residuals, vcov, stderror, nobs, dof and dof_residual. Each one stores every tuning choice on the fit and shows it with show.

Scalar-on-function regression

FPCRegression fits a Gaussian scalar response to one or more functional covariates and optional scalar covariates:

\[y_i = \alpha + z_i^\top\gamma + \sum_j\sum_{k=1}^{K_j} b_{jk}\xi_{ijk} + \epsilon_i, \qquad \beta_j(t)=\sum_{k=1}^{K_j}b_{jk}\phi_{jk}(t).\]

FPCA scores describe centered curves. Dense fits use the stored quadrature weights, including on nonuniform grids. Basis fits use exact basis inner products. Sparse fits use the existing PACE conditional expectation scores. The regression uses an intercept and ordinary least squares, with no regression smoothing parameter. The intercept is for centered functional covariates and uncentered scalar covariates. A deliberately uncentered basis FPCA retains its own score convention; its intercept must be interpreted in that convention.

Fit and inspect a model

The offline Tecator sample contains three spectra and their fat percentages. One component leaves one residual degree of freedom. This example illustrates the interface; use the full dataset for a substantive analysis.

using FunctionalDataAnalysis
import StatsAPI
tecator = load_dataset(:tecator; sample=true)
model = StatsAPI.fit(FPCRegression, tecator.data, tecator.covariates.Fat;
    ncomponents=1)
(StatsAPI.coef(model), model.sigma2, StatsAPI.r2(model))
([23.666666666666668, 5.102259160553306], 2.8299089563385644, 0.9943905178405669)
beta = only(coefficient_functions(model))
values = evaluate(beta, tecator.data.grid)
pointwise = only(coefficient_bands(model))
coordinates = band_data(pointwise) # band_plot(pointwise) uses the existing ribbon recipe
predictions = predict(model, tecator.data; interval=:prediction)
(StatsAPI.fitted(model), predictions.lower, predictions.upper)
([21.139638843526885, 40.615810200313334, 9.24455095615979], [-3.65939474387374, 11.10632947000618, -19.015121285811666], [45.93867243092751, 70.12529093062048, 37.50422319813125])

Pass a tuple of functional datasets, or MultivariateFunctionalData, for multiple predictors. Domains and sampling designs may differ. Subjects must have the same row order; conflicting subject IDs throw. For example, fit(FPCRegression, (x1, x2), y; scalar_covariates=Z, ncomponents=(2, 1)) fits two and one components, respectively.

coef orders parameters as intercept, scalar coefficients, then the score coefficients of each functional covariate. vcov and stderror use that same order. coefficient_functions returns a tuple of BasisFunctionalData, even for one predictor. This preserves exact basis eigenfunctions when available. fitted, residuals, nobs, dof, dof_residual and r2 follow StatsAPI. Here dof counts regression coefficients, and sigma2 is RSS divided by dof_residual. Rank deficiency, nonfinite inputs, zero response variation and nonpositive residual degrees of freedom throw informative errors. Nullable response and scalar containers are accepted when every entry is finite and observed; actual missing values throw and no subjects are dropped. The solve uses Julia's pivoted QR. Iterative proximal or coordinate descent methods, including ProximalSolvers.jl and CoordinateDescent.jl, would add iteration and stopping choices to this unpenalized least-squares problem; no optimization solver or runtime dependency is added.

fpca_options=(; max_k=5) passes settings to FPCA. For different settings per predictor, pass a tuple of named tuples. All smoothing, noise and eigenanalysis choices remain in each marginal FPCA, and are shown with the regression fit. See FPCA for defaults and existing departures from R, including the estimated measurement-noise floor. Regression does not add a second smoother or conditional expectation solver.

A supplied fpca may be one fit or a tuple/vector with a fit or nothing per covariate. The model copies supplied fits. It uses stored scores only for observations equal to the fit's stored training data; different observations are projected with that fit. This also preserves fitted preprocessing and FACE completion for training observations. Tuning options for supplied fits throw. ncomponents may choose a fixed count or an existing FPCA selector per fresh fit; for supplied fits it may retain or truncate the available harmonics using a fixed count or FVE. It cannot recover discarded eigenfunctions.

Optional regression selection uses selection=AIC(), BIC() or :loocv. Use fpca_options=(; max_k=...) to limit fresh candidate bases. AIC and BIC minimize n*log(RSS/n) + c*dof, with c=2 or log(n). The additive Gaussian likelihood constant is omitted. LOOCV minimizes mean squared held-out response error and refits FPCA in every fold, so it costs n FPCA fits per covariate for each candidate count tuple; keep max_k small with several covariates. Supplied fits are rejected for LOOCV because the procedure that produced them is not recoverable in general. Selection searches all positive leading-component counts, jointly across predictors. It records candidate counts, criteria, failures and the winner. Nonestimable candidates receive infinite criterion with an explicit reason; if none is estimable, fitting throws. Exact ties choose the first lexicographic count. Candidate search can be expensive with many predictors.

These are leading-component models. fda.usc fregre.pc.cv instead normally performs stepwise component subset selection. It defaults to kmax=8 and criteria="SIC"; neither overrides fdapace's FVE default here. Its AIC/SIC values are the corresponding package criterion divided by n. Its CV source refits FPCA but additionally divides each held-out residual by n-ck, where ck=n-out$df.residual for the fold. The package deliberately uses ordinary LOOCV prediction MSE, without this extra scaling, to measure held-out prediction error directly. The reference script compares that documented quantity using real fregre.pc fold fits and also saves the scaled R quantity.

Prediction and uncertainty

Native prediction reuses each stored FPCA fit. PACE accepts grid and irregular observations within its domain. Dense FPCA requires its complete training grid. Basis FPCA requires its training basis. New basis curves can be evaluated exactly on a raw fit's grid. Other conversions require an explicit evaluator=PiecewiseLinear() or NoInterpolation(); every curve must cover the fitted grid. For a basis fit this explicitly requests numerical projection using its stored work-grid quadrature, which approximates exact basis integration. No interpolation or basis approximation is chosen implicitly.

coefficient_bands, fitted_bands and predict(...; interval=:confidence) use the conditional OLS covariance sigma2*(D'D)^(-1), computed through pivoted QR and triangular solves. A confidence interval describes the conditional mean response. interval=:prediction adds independent Gaussian response noise. Returned interval objects record their target, alpha, critical value and uncertainty convention. These are pointwise intervals, with no simultaneous coverage claim. They exclude uncertainty in estimated means, eigenfunctions, sparse latent scores, truncation and model selection, and omit discarded modes. In particular, sparse intervals condition on the PACE score estimates.

fdapace FLM itself returns no standard errors. Its separate FLMCI defaults to level=0.95 and R=999 subject-bootstrap refits of FPCA and regression, reporting R quantile (type 7) percentile intervals. coefficient_bands(model; method=:bootstrap, B=999, rng) performs the same refits with the stored FPCA options and component rules; see Bootstrap intervals. The conditional default follows fda.usc's linear-model covariance and Student-t prediction formula.

Function-on-function regression

Pass a univariate functional response to FPCRegression. As in fdapace 0.6.0 FLM, the response is reduced to its own FPCA scores η_ik. Each response score is regressed by OLS on the same design of covariate scores (and scalar covariates), giving a p × K_Y coefficient matrix B:

\[\beta_j(t,s) = \sum_{k,l} \phi_{jk}(t)\, B_{jk,l}\, \psi_l(s), \qquad \hat Y_i(s) = \mu_Y(s) + \sum_l (D B)_{il}\,\psi_l(s).\]

using FunctionalDataAnalysis
import StatsAPI
grid = collect(range(0.0, 1.0; length=21))
u = 2pi .* (1:30) ./ 30
x = GridFunctionalData(cos.(u) .* transpose(sinpi.(grid)) .+
    0.5 .* sin.(2u) .* transpose(sinpi.(2grid)), grid)
y = GridFunctionalData(1 .+ (0.8cos.(u) .- 0.3sin.(2u)) .* transpose(sqrt(2) .* sinpi.(grid)) .+
    0.3 .* sin.(5u) .* transpose(cospi.(2grid)), grid)
fof = StatsAPI.fit(FPCRegression, x, y)
(ncomponents(fof), size(StatsAPI.coef(fof)), StatsAPI.r2(fof))
([2], (3, 2), 0.9419354838709678)
surface = only(coefficient_functions(fof))   # (; grid, response_grid, values)
intervals = only(coefficient_bands(fof))     # pointwise conditional surfaces
curves = StatsAPI.predict(fof, x[1:3])       # GridFunctionalData on the response grid
r2_by_time = pointwise_r2(fof)
size(surface.values), size(curves.values)
((21, 21), (3, 21))

The response FPCA is controlled like the covariates: response_fpca supplies a fit, response_fpca_options tunes a fresh one, and response_ncomponents fixes or truncates its count. Surfaces have the covariate grid t in rows and the response grid s in columns, the orientation of fdapace's betaList. The intercept function μ_Y(s) + B_{0·}ψ(s)' is reconstruct(fof.response_fpca, reshape(StatsAPI.coef(fof)[1, :], 1, :)).

pointwise_r2(fof) returns 1 - Σ_i r_i(s)² / Σ_i (Ỹ_i(s) - mean(s))² for the reconstructed responses Ỹ. fdapace reports only the scalar R2. Where every retained response eigenfunction vanishes (for example at the endpoints of sine eigenfunctions), the ratio is 0/0 and the value is NaN.

Conditional intervals use the variance φ_j(t)'(D'D)^(-1)_{jj}φ_j(t) · ψ(s)'SigmaE ψ(s) for β_j(t,s). Prediction intervals for a new response curve add ψ(s)'SigmaE ψ(s). These intervals condition on both FPCAs. They exclude truncation and measurement error of the response, which are not part of its retained components.

Bootstrap intervals

coefficient_bands(model; method=:bootstrap, B=999, alpha=0.05, rng=nothing) follows fdapace 0.6.0 FLMCI for scalar and functional responses. Each replicate resamples subjects with replacement and refits every FPCA and the regression with the stored options and component rules. FVE selection may therefore choose a different number of components in each replicate. The refitted coefficient functions are evaluated on the requested grids, and R type-7 quantiles give pointwise percentile intervals. se is the bootstrap standard deviation and critical_value is nothing.

As in FLMCI's dense branch, a resample is redrawn until every functional variable keeps its original observed time range, so refitted work grids agree. After 1000 consecutive rejections the call throws. FLMCI's sparse branch instead samples from all but 2(p+1) curves, then appends curves forced to contain each boundary. The package uses plain subject resampling with the range check for every design. Bootstrap intervals require fresh FPCA fits and selection=:fpca. Supplied fits throw because their fitting procedure cannot be repeated. rng=nothing uses Random.default_rng(). The RNG is copied, so the caller's state is unchanged, and its initial state is stored as settings.rng_state. A replicate that fails to refit throws with its number; no draw is dropped. FLMCI passes optnsListY as the covariate options of its point estimate, an apparent slip; the package uses the fitted model itself.

Concurrent regression

ConcurrentRegression implements fdapace 0.6.0 FCReg. fdapace 0.6.0 no longer contains ConcurReg; FCReg is its successor with the same two-dimensional smoothing estimator. Dense and sparse designs use the same code, and covariates and the response may be observed at different times:

\[\beta(t) = C_{XX}(t,t)^{-1} C_{XY}(t,t), \qquad \beta_0(t) = \mu_Y(t) - \sum_j \beta_j(t)\mu_j(t).\]

using FunctionalDataAnalysis
import StatsAPI
grid = collect(range(0.0, 1.0; length=11))
u = 2pi .* (1:30) ./ 30
x = GridFunctionalData(cos.(u) .* transpose(1 .+ grid) .+
    0.5 .* sin.(2u) .* transpose(cospi.(grid)) .+ transpose(grid), grid)
y = GridFunctionalData(transpose(1 .+ 0.5grid) .+ x.values .* transpose(1.2 .- 0.8grid) .+
    0.1 .* sin.(7u) .* transpose(cospi.(3grid)), grid)
concurrent = StatsAPI.fit(ConcurrentRegression, x, y;
    mean_bandwidth=0.15, covariance_bandwidth=0.2)
StatsAPI.coef(concurrent)   # intercept row, then one row per covariate
2×11 Matrix{Float64}:
 1.00601  1.04237  1.08665  1.13588   …  1.39373   1.44306   1.49219
 1.21708  1.12517  1.03704  0.950863     0.550403  0.479802  0.413827

Each functional variable is centered by a local linear mean evaluated at its own sorted unique observation times. Linear interpolation, with constant extrapolation as in approxfun(rule=2), gives the mean elsewhere. All within-subject products of centered values are smoothed by the existing bivariate local linear smoother (KernelSmoothing.jl) with unit weights and the covariance bandwidth on both axes. Only the diagonal (t,t) is evaluated. With measurement_error=true, a variable's own products drop equal-time pairs (FCReg's rmDiag), removing noise variance from C_XX and C_YY. Scalar covariates add varying coefficients. Their products with functional variables are smoothed by the univariate local linear smoother; their own covariances are sample covariances. pointwise_r2 returns FCReg's R2(t) = C_YX β / C_YY, clipped to [0,1].

predict(concurrent, x) returns GridFunctionalData on the fitted grid. Covariates completely observed on exactly that grid, and basis curves, are used directly. Other raw curves need an explicit evaluator=PiecewiseLinear() or NoInterpolation() and must cover the grid. Sparse curves usually do not, so fitted is available for dense data only. coefficient_bands(concurrent; B=999, rng) resamples subjects and refits the means and covariances with the stored bandwidths, kernel, grid and noise setting. It returns pointwise percentile intervals for the intercept and every coefficient; the bandwidth is not reselected and smoothing bias is ignored.

Function-on-scalar regression

FunctionOnScalarRegression implements fda 6.3.0 fRegress with scalar covariates and a fixed fdPar penalty. The response must be BasisFunctionalData; convert raw curves explicitly, for example with to_basis or smooth_curves. Each coefficient function uses the response basis, and the coefficients solve

\[\bigl(X^\top X \otimes G + \operatorname{blockdiag}(\lambda_k R_k)\bigr)\, b = \operatorname{vec}(G\, Y^\top X),\]

with exact Gram matrix G and penalty matrices R_k from the package's bases.

using FunctionalDataAnalysis
import StatsAPI
basis = BSplineBasis(4, (0.0, 1.0), 7)
u = 2pi .* (1:30) ./ 30
z = cos.(u)
coefs = 1 .+ z .* transpose(sin.(1:7) ./ 2) .+ 0.1 .* sin.(3u) .* transpose(cos.(1:7))
fos = StatsAPI.fit(FunctionOnScalarRegression, z, BasisFunctionalData(coefs, basis); lambda=1e-4)
intercept, slope = coefficient_functions(fos)
bands = coefficient_bands(fos)          # pointwise intervals, intercept first
StatsAPI.predict(fos, [0.5, -0.5])      # BasisFunctionalData
BasisFunctionalData{Float64}(n=2, nbasis=7)

Standard errors follow fRegress.stderr, Var(b) = C^(-1) (X'X ⊗ G Σ_c G) C^(-1), where Σ_c is the covariance of one response's basis coefficients (y2cMap*SigmaE*y2cMap' in fda). Reference source audit and validation

The audited sources are fdapace 0.6.0 (FLM.R, FLMCI.R, SetOptions.R, GetBR2New, FCReg with its demean, MvCov, uniCov, GetCrCovYZ, GetRawCrCovFuncFunc and Lwls2D helpers), fda.usc 2.2.0 (fregre.pc.R, fdata2pc.R, predict.fregre.fd.r, inprod.fdata.R, ops.fda.usc.R) and fda 6.3.0 (fRegress.fd, fRegress.double, fRegress.formula, fRegress.stderr, fRegressArgCheck, fdPar, inprod, bsplinepen, times.fd). The reference generators use R 4.5.1.

FLM fits marginal FPCA without changing its defaults, concatenates xiEst and scalar columns, then calls lm. Sparse predictors therefore use PACE CE scores through the ordinary FPCA route. Held-out curves use predict.FPCA with the training component count. fregre.pc defaults to l=1:3, lambda=0 and unit observation weights. The package follows fdapace's FVE default because it adapts the count to the functional predictor. A fixed ncomponents=3 provides the corresponding three-leading-component model. With a functional response, FLM fits the response FPCA with optnsListY and calls GetBR2New, which runs one lm per response score. Its alpha subtracts a rectangular integral of μ_j β_j; the package's intercept function is the centered one.

There are inherited discretization differences. fdapace uses rectangular covariance eigenanalysis and then trapezoidal harmonic normalization; fda.usc uses Euclidean SVD with uniform-grid normalization. Its inner-product helper is named int.simpson2, but the global int.method default is "TRAPZ". The package consistently uses stored quadrature weights. Dense and sparse golden fixtures use sine subspaces vanishing at the endpoints, where these eigensteps agree. Sparse fixtures supply the same mean, covariance and noise to isolate the regression and CE route from existing smoother differences. The package's centered intercept is compared with the R score-regression intercept: FLM$alpha instead subtracts a rectangular integral of mu*beta.

FCReg centers each variable with GetSmoothedMeanCurve at its unique times, then calls MvCov with center=FALSE. The functional-functional blocks smooth raw products with Lwls2D(crosscov=TRUE) and exclude equal-time pairs of a variable with itself under measurementError. Functional-scalar blocks use Lwls1D. Its coefficient solve is qr.solve at each output point. Its summaryConReg helper is empty; no intervals or bandwidth defaults exist.

fRegress.fd forms its normal equations with inprod, which integrates by Romberg extrapolation with relative tolerance 1e-4 unless both arguments are B-spline objects passed with integer derivative orders. With interior knots this leaves relative errors near 1e-5 in the fitted coefficients. The package uses exact Gram matrices. bsplinepen computes B-spline penalties exactly for bases with interior knots, but for a B-spline basis without interior knots it substitutes a monomial basis and returns that basis's penalty matrix, which does not apply to B-spline coefficients. Penalized fRegress fits on such bases therefore differ from the B-spline penalty used here. fRegress.stderr integrates with a sum over 501 equally spaced points that gives full weight to both endpoints; the exact inner products here change its covariance by up to about 8% in the reference fixtures. Fitted curves are projected onto the response basis on 501 points by smooth.basis; the package's fitted coefficients are exact.

Recreate the small fixtures from the repository root with Rscript test/reference/regression_m7.R (fdapace 0.6.0 and fda.usc 2.2.0) and Rscript test/reference/regression_m7b.R (fdapace 0.6.0 and fda 6.3.0). test/regression.jl compares scalar-response coefficient functions, scalar coefficients, fitted values, residuals, residual variance, R², held-out predictions and conditional intervals at relative error below 1e-8. It also checks full-refit LOOCV and AIC/BIC against R, and independent analytic nonuniform-grid, basis and sparse conditional-expectation examples. test/regression_functional.jl compares, at relative error below 1e-8:

  • dense and sparse functional-response FLM fits: surfaces, fitted and predicted curves, response scores, score coefficients, R2, pointwise R² (away from the vanishing endpoints) and the conditional standard errors;
  • dense (with a scalar covariate, and without measurement error) and sparse FCReg coefficients, intercepts and R2(t);
  • fRegress itself for an unpenalized B-spline basis without interior knots, where Romberg integration is exact, and otherwise the same normal equations recomputed in R with exact bsplinepen (or exact Gauss–Legendre) matrices, together with the fRegress.stderr covariance, pointwise standard errors and predictions using exact inner products.

Analytic checks cover noise-free surfaces, bootstrap intervals that collapse when every resample refits the same model, a replay of the bootstrap draws, and orthonormal-basis least squares. No R installation is required to use the package or run its tests.

Penalized scalar-on-function regression

PenalizedFunctionalRegression fits the same Gaussian model with each coefficient function expanded in a spline basis and penalized for roughness, as refund's pfr(y ~ z + lf(X1) + lf(X2), method="REML") (Goldsmith, Bobb, Crainiceanu, Caffo and Reich 2011):

\[y_i = \alpha + z_i^\top\gamma + \sum_j \sum_t L_{jt} X_{ij}(t)\, B_j(t)^\top b_j + \epsilon_i, \qquad \text{penalty } \sum_j \lambda_j b_j^\top S_j b_j .\]

L_jt are integration weights on the covariate grid, B_j a basis and S_j its penalty. Each functional covariate has its own smoothing parameter, chosen by REML through PenalizedLeastSquares (the solver of the Penalized fitting page). The intercept and scalar covariates are unpenalized.

using Random
rng = Xoshiro(7)
grid = collect(range(0, 1; length=40))
shapes = hcat(ones(40), grid, sinpi.(grid), cospi.(grid), sinpi.(2 .* grid), cospi.(2 .* grid))
X = randn(rng, 80, 6) * transpose(shapes) .+ 0.05 .* randn(rng, 80, 40)
z = randn(rng, 80)
y = 1 .+ 0.5 .* z .+ X * (quadrature_weights(grid) .* sinpi.(2 .* grid)) .+ 0.1 .* randn(rng, 80)
x = GridFunctionalData(X, grid)
penalized = StatsAPI.fit(PenalizedFunctionalRegression, x, y; scalar_covariates=z)
(penalized.lambda, penalized.edf_terms, penalized.sigma2, StatsAPI.coef(penalized)[1:2])

Prediction intervalsinterval=:none; requested intervals use Vp (mgcv predict.gam) and normal quantiles

A BSplineBasis or any other basis covering the grid can be supplied with basis=..., penalized by penalty(basis, penalty_order) (default order 2). Pass a tuple of options for several covariates, for example k=(10, 6) or presmooth=(nothing, :fpca). Fixed lambda (one value per covariate, in units of the rescaled penalties like mgcv's sp) skips selection. Every choice is stored in settings and the per-term terms records (grid, weights, basis, penalty, scale, presmoother and processed training curves), and is shown by show.

Integration weights. refund's "simpson" weights are (t_J - t_1)/J/3 * [1, 4, 2, 4, …, 2, 1]. They divide by the number of points J instead of the J-1 intervals and are not Simpson's rule when J-1 is odd, so every β is inflated by about J/(J-1) (5% on 21 points). The package therefore integrates with the grid's stored trapezoidal weights, the same weights it uses for every other inner product and identical to refund's integration="trapezoidal". integration=:refund_simpson and :riemann reproduce refund's two other formulas exactly, and a weight vector may be supplied.

Sparse, noisy and basis covariates

Grid covariates with missing values and irregular covariates need a presmoother, as in refund, where lf(presmooth=) reconstructs curves before fitting. :bspline fits cubic B-splines per curve by least squares, with interior knots at quantiles of the grid as R's splines::bs(df=nbasis, intercept=TRUE). :interpolate interpolates observed values linearly and holds them constant beyond the first and last observation (R approx(rule=2)). :fpca fits the package's FPCA (PACE for sparse data, with presmooth_options passed to fit(FPCA, ...)) and uses its reconstruction mean + scores × eigenfunctions on the FPCA work grid or a supplied grid; refund uses its own fpca.sc, fpca.face or fpca.ssvd here, so this option is not numerically comparable to refund. New subjects are presmoothed with the stored presmoother: projected onto the training FPCA, or smoothed per curve. Basis covariates are evaluated exactly on a required grid. Only the presmoothed curves enter the regression: as in refund, presmoothing and FPCA uncertainty are not propagated to the covariances or bands.

Uncertainty

vcov(fit; type=:bayesian) is the posterior covariance (XᵀX + S_λ)⁻¹σ² (mgcv Vp), :frequentist is mgcv Ve, and :corrected is mgcv's Vc. Vc adds a first-order term J V_ρ Jᵀ, with J = ∂b̂/∂log λ and V_ρ the inverse Hessian of the REML criterion over (log λ, log σ²), and the second-order Cholesky-derivative correction of Wood, Pya and Säfken (2016), both as in mgcv 1.9-3 gam.fit3.post.proc. It exists only after REML selection, and settings.corrected_covariance says whether it was computed (:mgcv_Vc). When a smoothing parameter is effectively infinite, XᵀX + S_λ is numerically singular and the derivatives with respect to log λ carry no information, so Vc is not formed (:unavailable_infinite_lambda); the same holds if the Cholesky factorization fails (:unavailable_not_positive_definite). Bands and intervals then default to Vp. mgcv still reports a Vc in these cases. Bands are pointwise normal intervals. refund offers no simultaneous bands for pfr, and none are returned. dof is the total effective degrees of freedom (intercept and scalar coefficients included), edf_terms the effective degrees of freedom of each functional term, and sigma2 mgcv's RSS/(n - dof).

Choosing a regression method

Both fits return a tuple of coefficient functions, coef, vcov, fitted, residuals, predict and coefficient_bands, so downstream code can use either. FPC regression truncates to leading components of the covariate and conditions on the FPCA; it suits strongly smooth covariates whose leading modes carry the signal, and sparse designs through PACE scores. Penalized regression lets the response choose the smoothness of β through REML, does not tie β to the leading covariate modes, accounts for smoothing parameter uncertainty in its bands, and is the better choice when β has features in directions of small covariate variance or when several dense covariates need separate smoothness.

The regression study compares three fits with their default settings:

  • fit(FPCRegression, x, y);
  • the same fit with selection=BIC();
  • fit(PenalizedFunctionalRegression, x, y), with presmooth=:fpca for sparse curves.

Covariates are simulated with simulate_kl from nine Fourier components with eigenvalues 1/k². They are observed with noise either on a dense grid or at 2–10 random times per curve. The coefficient β(t) takes three forms:

  • aligned with the two leading eigenfunctions;
  • equal to the trailing eigenfunction, which FVE(0.99) drops in population;
  • a smooth bump unrelated to the eigenfunctions (Reiss and Ogden 2007).

The other factors are n ∈ {100, 500} and a population R² of 0.8 or 0.5, with 200 replicates per cell. The study records:

  • relative error of β̂;
  • prediction error on held-out subjects;
  • pointwise coverage of the default 95% bands;
  • component counts or effective degrees of freedom;
  • time, allocations and failures.

Neither method offers simultaneous bands. The study instead reports how often the pointwise band covers all of β. Note that on noisy dense curves the default dense FPCA does not smooth, so FVE(0.99) also keeps noise-dominated components. Use selection=BIC(), ncomponents, or a smoothing FPCA (fpca_options=(; method=:face)) to control the count.

refund and mgcv source audit

The audited sources are refund 0.1-40 (pfr.R, lf.R, create.prep.func.R, coefficients.pfr.R, predict.pfr.R) and mgcv 1.9-3 (smooth.construct.tp.smooth.spec, tprs.c, smoothCon, gam.fit3.post.proc, Vb.corr, vcorr, dchol). Findings:

  • pfr rewrites each lf(X) as s(X.tmat, by=L.X) with matrix arguments, so the term is Σₜ L_t X(t) f(t) (mgcv's summation convention) and calls gam(method="REML"). A centering constraint is added only when the row sums of L*X are constant; the package throws instead, because the term is then confounded with the intercept.
  • mgcv computes the penalty scale from the unweighted basis at the grid, before the by weights are applied, and rescales thin plate columns to unit root mean square.
  • The thin plate basis uses η(r)=|r|³/12, the k eigenvalues of largest magnitude by Lanczos iteration (tolerance eps^0.7) and a Householder absorption of Tᵀδ = 0. On grids symmetric about their mean (every uniform grid) the absorption depends on entries that are zero in exact arithmetic, so mgcv's columns there depend on rounding in its eigenvectors. The function space, the penalty, β, fitted values, Vp and Ve do not; mgcv's Vc does, through its Cholesky-based second-order term.
  • lf() integration weights are as described above; predict.pfr reuses the training weights and presmoother for new curves on the training grid.
  • coef.pfr uses Vc by default and returns standard errors only; fpca.ssvd presmoothing cannot predict new curves (refund warns).

Validation

Recreate the fixture with Rscript test/reference/refund_m7_pfr.R (R 4.5.1, refund 0.1-40, mgcv 1.9-3). test/pfr.jl compares, at relative error below 1e-8: the thin plate basis and penalty (up to column signs) on three point sets, including the untruncated case; and, for one functional covariate, two functional covariates, GCV, and B-spline presmoothing (the package's trapezoidal default against refund's integration="trapezoidal"), and for refund's default integration="simpson" on a uniform grid (through integration=:refund_simpson), each with a scalar covariate, the intercept and scalar coefficients, fitted values, σ², the criterion, per-term and total EDF, β and its Vp standard errors on refund's default grid, and held-out predictions with standard errors. These comparisons are made at refund's selected smoothing parameters, and the package's own optimum is checked to be no worse under the criterion. mgcv's Vc standard errors are compared on the grids that are not symmetric about their mean, where mgcv's basis is deterministic. No R installation is needed to use the package or run its tests.

Fields include pls (the PenalizedLeastSquares fit), lambda, edf_terms, penalty_scale, sigma2, terms (grids, integration weights, bases, penalties, presmoothers and the processed training curves) and settings. See the Regression documentation for the refund audit.

FunctionalDataAnalysis.ThinPlateRegressionBasis — Type
ThinPlateRegressionBasis(points, k=10)

The rank-k thin plate regression spline basis of mgcv 1.9-3 s(x, bs="tp") in one dimension, with penalty order m = 2 (∫f''(t)²dt). It is refund's default lf() basis, where k=10 is mgcv's default dimension.

The finite points (usually a covariate grid; ties are merged) are the knots of the full spline. Their mean is subtracted for stability (mgcv shift). With η(r) = |r|³/12 and E[i,j] = η(xᵢ-xⱼ) over the u distinct points, the basis keeps the eigenvectors U of the k eigenvalues of E of largest magnitude (ordered by decreasing value), imposes Tᵀδ = 0 for the null-space polynomials T = [1, x] by mgcv's Householder factorization, and appends T. Functions are f(t) = Σⱼ η(t-xⱼ)δⱼ + α₀ + α₁t with [δ; α] = UZ * γ. As in mgcv, every column is scaled to unit root mean square over the supplied points. When u == k no eigen truncation is applied. mgcv uses a Lanczos iteration with relative tolerance eps^0.7; this basis uses LAPACK's symmetric eigensolver, so it agrees with mgcv up to column signs and the Lanczos tolerance. On points symmetric about their mean, some Householder signs in mgcv's construction are decided by rounding noise; this basis uses the exact-arithmetic choice, so its columns can then differ from mgcv's by a rotation of the same function space and penalty.

The domain is the range of points. penalty(b, 2) integrates f''² exactly over the domain (the functions are natural cubic splines, so this equals mgcv's penalty γᵀSγ, available unscaled as b.penalty). basis_matrix supports derivatives of any order (zero beyond the third).

FunctionalDataAnalysis.FPCRegression — Type
FPCRegression
fit(FPCRegression, x, y; scalar_covariates=nothing, fpca=nothing,
    fpca_options=(;), ncomponents=nothing, selection=:fpca,
    response_fpca=nothing, response_fpca_options=(;), response_ncomponents=nothing)

Gaussian regression on leading FPCA scores. x is one univariate functional dataset, a tuple/vector of them, or MultivariateFunctionalData. y is a finite response vector, or one univariate functional dataset (grid, irregular or basis) for function-on-function regression. Scalar covariates are an optional finite vector or matrix, without an intercept column.

For a scalar response the model is y = intercept + Z*gamma + sum(scores_j*b_j) + error; coefficient_functions returns each beta_j = eigenfunctions_j*b_j. coef and vcov order parameters as intercept, scalar coefficients, then score coefficients in covariate order. dof is their count and dof_residual = nobs-dof. sigma2 is residual sum of squares / residual dof. Rank-deficient designs, saturated models and constant responses throw.

For a functional response, y is reduced to its own leading FPCA scores eta_ik and each response score is regressed on the same design, as fdapace 0.6.0 FLM (GetBR2New) does. Then beta_j(t,s) = phi_j(t)' B_j psi(s)', with covariate eigenfunctions phi_j and response eigenfunctions psi. coef returns the p × K_Y matrix B (rows in the scalar-response order, one column per response component), vcov the covariance of vec(B), SigmaE ⊗ inv(D'D), where SigmaE is the residual score cross-product divided by dof_residual = nobs - p. stderror has the shape of coef; dof counts all p*K_Y coefficients. sigma2 is tr(SigmaE), the integrated residual variance within the retained response components, and r2 is fdapace's score-scale R², 1 - sum(RSS_k)/sum(TSS_k). The response FPCA follows the covariate rules: response_fpca supplies a fit (copied; its stored scores are reused only for its own training data), response_fpca_options tunes a fresh one (fdapace's optnsListY=list() default is the FPCA defaults, including FVE(0.99)), and response_ncomponents fixes or truncates its count. Regression selection (AIC, BIC, :loocv) is not defined for functional responses and throws; fdapace FLM uses only FPCA selection.

By default each covariate is fitted with its own fit(FPCA, x_j) defaults, including FVE(0.99), following fdapace 0.6.0 FLM. fpca can supply a fitted FPCA or a tuple/vector with one fit (or nothing) per covariate. fpca_options is a named tuple shared by newly fitted covariates, or a corresponding tuple/vector of named tuples. Options for supplied fits throw. ncomponents is nothing (keep each FPCA's selection), a common positive integer or FPCA selector, or a tuple/vector of these. Supplied fits can be truncated to a fixed count or FVE within their stored harmonics. They are copied; stored training scores are used only when the covariate equals their copied training data; otherwise existing FPCA prediction scores are used.

selection=AIC() or BIC() minimizes the Gaussian regression criterion over all positive leading-component counts, conditional on the fitted FPC bases. selection=:loocv minimizes held-out squared response error, refitting FPCA in every fold, as fda.usc 2.2.0 fregre.pc.cv does. It omits that source's extra residual scaling by n-ck to target ordinary prediction MSE. Its cost is n FPCA fits per covariate for every candidate count tuple, so it grows with n times the product of the counts searched; cap them with max_k. Fold fits are not reused across counts because sparse (PACE) scores depend on the number of retained components. Supplied fits are unsupported for this selector: an external fitting procedure cannot be refitted faithfully. Regression selection cannot be combined with ncomponents or an FPCA option named ncomponents; use max_k in fpca_options to cap fresh fits. All candidates, criteria and failures are stored. Ties choose the first lexicographic count. Nonestimable candidates have infinite criterion and a recorded reason.

The joint leading-count search extends fda.usc's one-predictor selection, using leading counts instead of its stepwise component subsets; fdapace FLM itself uses only FPCA selection. No smoothing penalty is fitted. OLS uses Julia's pivoted QR, with numerical rank tolerance max(size(design)...)*eps(T)*maximum(abs, diag(R)), stored in settings. All inputs and tuning choices are copied. See the Regression documentation for reference defaults, scale differences and conditional uncertainty.

FPCA means, harmonics, sparse scores, component selection and omitted components are treated as fixed. For a functional response the variance of beta_j(t,s) is phi_j(t)'C_jj phi_j(t) * psi(s)'SigmaE psi(s).

method=:bootstrap gives fdapace 0.6.0 FLMCI percentile intervals: B subject resamples (default 999, FLMCI's R) each refit every FPCA (with the stored options and component rules) and the regression, and R type-7 quantiles of the refitted coefficients give the interval. As in FLMCI's dense branch, a resample is redrawn until every functional variable has the original observed time range, so refitted work grids agree; 1000 consecutive rejections throw. Refitted coefficients are evaluated on the requested grids. se is the bootstrap standard deviation and critical_value is nothing. Bootstrap intervals require fresh FPCA fits and selection=:fpca; supplied fits throw because their fitting procedure cannot be repeated. rng=nothing uses Random.default_rng(); the RNG is copied (the caller's state is unchanged) and its initial state is stored in settings.rng_state. FLMCI samples sparse data from a subset of curves plus forced boundary curves; this package uses plain subject resampling with the range check for every design. All intervals are pointwise, not simultaneous bands.

FunctionalDataAnalysis.pointwise_r2 — Function
pointwise_r2(f; grid=nothing)

Return (; grid, values) with a pointwise coefficient of determination. For a functional-response FPCRegression this is 1 - sum_i r_i(s)^2 / sum_i (Y_i(s) - mean(s))^2 for responses reconstructed from their retained FPC scores, on the response FPCA work grid or a supplied grid. fdapace 0.6.0 reports only the scalar score-scale R². StatsAPI.predict — Method
predict(f::FPCRegression, x; scalar_covariates=nothing, evaluator=nothing,
    interval=:none, alpha=0.05, grid=nothing)

Predict new responses using stored FPCA fits and component counts. interval=:none returns a vector (scalar response) or GridFunctionalData of predicted curves mean_Y + D*B*psi' (functional response) on the response FPCA work grid or a supplied grid. :confidence and :prediction return pointwise conditional Student-t intervals with estimate, se, lower, upper, alpha, critical_value, and settings (functional responses add grid; arrays are subject × grid). Prediction intervals add f.sigma2 for a new independent Gaussian response, or psi(s)'SigmaE psi(s) for a new response curve within the retained response components. All FPCA/score estimation and selection uncertainty is excluded, including latent sparse score variance.

Native FPCA representations use its existing prediction contract: PACE accepts both raw types, dense FPCA uses its complete training grid, and basis FPCA uses its training basis. Basis curves can be evaluated exactly on a raw fit's grid. For other representations, explicitly pass evaluator=PiecewiseLinear() or NoInterpolation() (one per covariate is allowed). Curves must cover the fitted grid. For a basis fit this explicitly requests numerical projection on its stored work-grid quadrature, an approximation to exact basis integrals. No mean, covariance or eigenfunction is refitted. Exact training observations reuse the stored training scores, including FACE completion and preprocessing.
