Smoothing

Per-curve smoothing accepts grid or irregular observations. Masked values are unobserved. Local polynomials require a scalar bandwidth and an explicit work grid. They leave points outside each curve's observed range missing. An undefined estimate within that range raises an error suggesting a larger bandwidth. Kernels come from KernelSmoothing.jl.

using FunctionalDataAnalysis
import KernelSmoothing
import StatsAPI

t = collect(range(0.0, 1.0; length=21))
fd = GridFunctionalData(permutedims(hcat(1 .+ t, 2 .- t)), t; ids=[:a, :b])
local_fit = smooth_curves(fd, LocalPolynomial(bandwidth=0.3); grid=t)
# The StatsAPI entry point returns the same kind of data object.
local_fit = StatsAPI.fit(LocalPolynomial, fd; bandwidth=0.3, grid=t)

basis = BSplineBasis(4, (0.0, 1.0), 6)
spline_fit = smooth_curves(fd, PenalizedSpline(basis; lambda=0.1))
selected = smooth_curves(fd,
    PenalizedSpline(basis; lambda=GCV([0.001, 0.01, 0.1, 1.0])))
selected.metadata.selection
(lambdas = [0.001, 0.01, 0.1, 1.0], scores = [5.19114495116702e-31, 1.4212241499582851e-31, 2.589317521775433e-30, 1.7199686189583488e-27], lambda = 0.01)

Both methods return functional data, with copied ids. Their metadata named tuple records all settings and is included in show. Constructors for grid and basis data also accept a copied metadata named tuple. Metadata describes the fit at creation; changing the public data arrays does not refit it. Local fits record bandwidth, degree, kernel, work grid, and minobs=0. Spline fits record basis, selected or fixed lambda, and derivative order. Both use equal observation weights, no binning, and no folds.

GCV chooses one common lambda by summing the per-curve criteria n_i * RSS_i / (n_i - tr(H_i))^2. Scores use actual observed times, including for curves with different observation counts. Every candidate and its score is retained in metadata.selection; fixed lambda sets selection=nothing. Singular candidate fits or residual degrees of freedom no larger than sqrt(eps(T))*n_i get infinite scores. No curve is dropped. All-infinite scores raise an error. Exact ties choose the first supplied candidate. This criterion concerns prediction within curves and does not account for within-curve error correlation.

Pointwise confidence bands for the pooled mean are outside this API. They require cluster-robust variances, which KernelSmoothing.jl does not yet provide. Covariance and noise variance are estimated as described below.

KernelSmoothing.jl is currently unregistered. On Julia 1.10, install it before instantiating this project (newer Julia versions use the root [sources]):

using Pkg
Pkg.add(url="https://github.com/mlakolar/KernelSmoothing.jl")

KernelSmoothing must be registered before FunctionalDataAnalysis can be registered.

FunctionalDataAnalysis.LocalPolynomial — Type
LocalPolynomial(; bandwidth, degree=1, kernel=KernelSmoothing.EpanechnikovKernel())

Per-curve local polynomial settings. Supply a finite positive scalar bandwidth; no automatic selector or nearest-neighbour bandwidth floor is used. Degree is a nonnegative integer. Kernels are KernelSmoothing.AbstractKernel instances. Use smooth_curves, or StatsAPI.fit(LocalPolynomial, fd; grid, bandwidth, ...).

FunctionalDataAnalysis.PenalizedSpline — Type
PenalizedSpline(basis; lambda, order=2)

Per-curve unweighted penalized least squares through to_basis. lambda is a finite nonnegative number or GCV selecting a common penalty. order is the nonnegative derivative order in the integrated squared roughness penalty. The basis and settings are copied. Use smooth_curves, or StatsAPI.fit(PenalizedSpline, fd; basis, lambda, order=2).

FunctionalDataAnalysis.GCV — Type
GCV(lambdas)

Select one common spline penalty from a copied, nonempty vector of distinct, finite nonnegative candidates. Minimize the sum over curves of n * RSS / (n - tr(H))^2, where H is the unweighted penalized least-squares smoother matrix at that curve's observed times. Singular fits and zero residual degrees of freedom receive Inf; no curves are dropped. Exact ties use the first supplied candidate. All scores are retained in the smoothed data's metadata.selection named tuple (lambdas, scores, lambda).

FunctionalDataAnalysis.smooth_curves — Function
smooth_curves(fd, method::LocalPolynomial; grid)
smooth_curves(fd, method::PenalizedSpline)

Smooth each observed curve of grid or irregular data, retaining copied subject ids. Local polynomials return GridFunctionalData on the explicit finite, strictly increasing work grid (at least two points). Points outside each curve's observed range are missing; no extrapolation occurs. Empty curves and nonfinite in-range estimates throw an ArgumentError identifying the curve and point and suggesting a larger bandwidth.

Penalized splines return BasisFunctionalData through to_basis. Both results store their method and all settings in metadata, shown by show. Spline GCV also stores metadata.selection; fixed lambda uses selection=nothing. All fits use equal observation weights, no binning, and no folds. GCV is a within-curve prediction criterion, not a cluster-robust inference procedure.

Pooled means and curve-level CV

StatsAPI.fit(SmoothedMean, fd; grid, bandwidth, weighting=:obs) pools all observed values. :obs weights each observation equally. :subj uses 1/N_i per observation so each curve has total weight one. Data-object observation and curve weights are not used by this API. Empty curves raise an error. The work grid is explicit; there is no binning or nearest-neighbour bandwidth floor. The sampling design is retained as design.

mean_fit = StatsAPI.fit(SmoothedMean, fd; grid=t, bandwidth=0.3)
evaluate(mean_fit, [0.25, 0.75])
cv_mean = StatsAPI.fit(SmoothedMean, fd; grid=t,
    bandwidth=CurveCV([0.2, 0.3, 0.5]; folds=nobs(fd)), weighting=:subj)
cv_mean.selection
(bandwidths = [0.2, 0.3, 0.5], errors = [0.3666666666666667, 0.3666666666666666, 0.3666666666666666], assignments = [1, 2])

evaluate returns linear interpolation on the stored grid, including its endpoints. It throws outside that range or for nonfinite queries. The pooled smoother itself can estimate beyond observed times when the kernel window has enough distinct times; undefined local fits raise an error naming the point.

CurveCV predicts held-out curves at their actual observation times, leaving out whole curves. Its error is the total weighted squared error divided by the total observation weight, using the same :obs or :subj scheme as the fit. Every candidate must yield finite predictions in every fold; otherwise selection throws and suggests a larger bandwidth. Ties select the first candidate. For K-fold selection, supply rng, for example CurveCV([0.3, 0.5]; folds=2, rng=MersenneTwister(42)) after using Random. Folds are shuffled and balanced in curve counts. The RNG state is copied, so reusing a selector repeats its split without advancing the caller's RNG. Leave-one-curve-out (folds=nobs(fd)) is deterministic and requires no RNG. The result stores candidate bandwidths, errors, per-curve fold assignments, fold count, and all smoothing settings; show displays them.

The fixed-bandwidth mean is checked against fdapace 0.6.0 Lwls1D, using Epanechnikov local linear fits without binning, for both weighting schemes. The reference script is test/reference/fdapace_m2.R. Run it from the repository root to recreate the version-labelled CSVs. The covariance fixture uses ordered within-curve off-diagonal residual products, centered at direct mean estimates at observation times, and Lwls2D(method="plain"). Its subject weights are 1/(N_i*(N_i-1)). The covariance tests compare this quantity to relative error below 1e-8. The mean is stored at all input times for this comparison, so centering agrees with the direct fdapace mean rather than a coarser interpolated mean.

FunctionalDataAnalysis.SmoothedMean — Type
fit(SmoothedMean, fd; grid, bandwidth,
    kernel=KernelSmoothing.EpanechnikovKernel(), degree=1, weighting=:obs)

Fit a local polynomial to all observed values of univariate grid or irregular data. :obs gives each observation weight one; :subj gives each observation in curve i weight 1/N_i. Stored data weights are not used. Empty curves throw. The explicit work grid must be finite and strictly increasing with at least two points. The required bandwidth is a positive number, CurveCV, or a regression KernelSmoothing.BandwidthSelector returning one global bandwidth. Selectors use the pooled observations and the chosen weights. They assume independent observations: asymptotically adequate for sparse designs, where each curve contributes about one point per window, but they ignore within-curve correlation in dense designs. Use CurveCV for the final choice. Density-only and pointwise bandwidth rules raise ArgumentError.

The fit stores grid, values, selected bandwidth, kernel, degree, weighting, sampling design (design), minobs=0, binning=:none, and folds (zero for a fixed or rule-selected bandwidth). Fixed bandwidths store selection=nothing. A rule stores rule, bandwidth, and selector details in selection. CV stores a named tuple of bandwidths, errors, and per-curve assignments. CV minimizes total weighted squared prediction error divided by total held-out weight, at actual observation times. An undefined fit, including any CV prediction, throws with its point and a suggestion to increase bandwidth. No observation or candidate is dropped. Use evaluate to interpolate linearly within the stored grid range; queries outside it throw. No confidence bands are provided.

FunctionalDataAnalysis.CurveCV — Type
CurveCV(bandwidths; folds=10, rng=nothing)
CurveCV(; pilot, multipliers=2.0 .^ range(-1, 2; length=10), folds=10, rng=nothing)

Select a pooled-mean, covariance, or noise-diagonal bandwidth by leaving out whole curves. Candidates must be finite, positive, and distinct. Supply an AbstractRNG for shuffled, balanced K-fold splits; folds == nobs(fd) uses deterministic leave-one-curve-out and needs no RNG. Inputs, including the RNG state, are copied. Each fit starts from that copied state. Exact score ties select the first candidate.

For the mean or noise diagonal, pilot is a regression KernelSmoothing.BandwidthSelector. At fit time its global bandwidth multiplies multipliers to form the candidates. The default ten multipliers range from 0.5 to 4 on a logarithmic grid. The pilot uses all pooled observations and the fit's weights. Selection records pilot, h_pilot, pilot_details, multipliers, bandwidths, errors, and assignments. The 2D covariance requires explicit candidates. Pilot rules assume independent observations. That is asymptotically adequate for sparse designs but ignores within-curve correlation in dense ones; use CurveCV for the final choice.

Covariance and noise variance

StatsAPI.fit(SmoothedCovariance, fd, mean_fit; grid, bandwidth, diagonal_bandwidth) smooths all ordered within-curve residual products with distinct observation indices. This excludes measurement noise on the raw diagonal. The product kernel uses the same scalar bandwidth in both coordinates. Local linear fits solve a three-coefficient weighted least-squares system; singular windows throw and name the query point. The final surface is symmetrized exactly. It is not projected onto the positive-semidefinite cone.

:obs assigns weight one to each pair. :subj assigns 1/(N_i*(N_i-1)) so each curve has total pair weight one. Each curve must have at least two observations; empty and singleton curves raise errors. The supplied mean is linearly interpolated at the original observation times. Its stored grid must cover all those times. Stored data weights are unused.

A CurveCV selector leaves entire curves out of the covariance smoother and predicts their raw products, minimizing weighted squared prediction error. The supplied mean remains fixed across folds; CV is conditional on that mean. This does not refit the mean within each training fold. Split rules, tie rules, and errors for undefined candidates follow the pooled-mean conventions above.

binning=n snaps original times onto the nearest of n equally spaced points spanning the observed domain. Midpoint ties go upward. Residuals are computed at the original times before snapping. Pair multiplicities and original observation-index diagonal exclusions are preserved, including products whose two distinct observations snap to the same bin. No observations are discarded. Within each curve and bin cell, pair weights are summed and products are replaced by their weighted mean. This preserves the fixed-bandwidth fit at snapped times. Within-cell squared errors are retained, so CV still scores the original raw products. Default binning=nothing disables snapping and aggregation.

Forming products takes O(P) work, where P = sum(N_i*(N_i-1)). Without binning, covariance CV takes O(P^2) work per candidate bandwidth. With binning, pair storage and CV use Q = sum(min(N_i*(N_i-1), n^2)) as an upper bound on the number of occupied curve/bin cells, reducing these costs to O(Q) storage and O(Q^2) CV work. Binning helps when many pairs share cells; it does not remove the cost of initially forming the products.

The noise estimator smooths raw residual squares by a univariate local linear fit with minobs=0. By default it uses the covariance bandwidth (after any CV selection), as fdapace does; theory only requires the diagonal bandwidth to be of no larger order than the covariance bandwidth, so this default is consistent (Li and Hsing, 2010, Corollary 3.5). Pass diagonal_bandwidth to choose it separately: a positive number, a CurveCV, or a KernelSmoothing regression rule (see below). noise_details.diagonal_source records :covariance or :user. Diagonal CV predicts the raw squared residuals of held-out curves at their original observation times, using the pooled-mean weighting and fold rules. The supplied mean remains fixed. When binning is enabled, training times are snapped as in the final diagonal smoother; held-out query times remain original. Its weights are one for :obs and 1/N_i for :subj. If this fit is V(t) and the covariance is G(s,t), the raw noise estimate is (2/(b-a)) * integral(V(t)-G(t,t), t=a+(b-a)/4..b-(b-a)/4). Here [a,b] is the work-grid range. Trapezoidal quadrature includes the exact middle-half boundaries, interpolating V-G linearly when needed. Negative estimates are truncated to zero. noise_details records the untruncated value, truncation flag, diagonal bandwidth, fold count, selection candidates, errors and assignments, fitted squares, and integration settings. diagonal_bandwidth also appears directly on the fit. The stored weights integrate over the full covariance work grid.

using Random
sparse = simulate_kl(MersenneTwister(42), 80; mean=t -> 1 + t,
    eigenfunctions=[t -> 1.0], eigenvalues=[0.5], noise_sd=0.2,
    sampling=SparseSampling((0.0, 1.0), 6:9)).data
workgrid = collect(range(0.0, 1.0; length=11))
pooled = StatsAPI.fit(SmoothedMean, sparse; grid=workgrid, bandwidth=0.8)
covariance = StatsAPI.fit(SmoothedCovariance, sparse, pooled;
    grid=workgrid, bandwidth=0.8, diagonal_bandwidth=0.6, weighting=:subj)
(size(covariance.surface), covariance.noise_variance, evaluate(covariance, 0.3, 0.6))
((11, 11), 0.028543152364387547, 0.5728052415713563)

evaluate(covariance, s, t) uses bilinear interpolation within the stored grid. Nonfinite queries and extrapolation raise errors. All tuning settings, the sampling design, CV results, and noise details appear in show.

FunctionalDataAnalysis.SmoothedCovariance — Type
fit(SmoothedCovariance, fd, mean::SmoothedMean; grid, bandwidth, diagonal_bandwidth=nothing,
    kernel=KernelSmoothing.EpanechnikovKernel(), weighting=:obs, binning=nothing)

Smooth all ordered within-curve off-diagonal residual products by bivariate local linear regression and symmetrize. The required bandwidth is positive or a CurveCV with explicit candidates. KernelSmoothing selectors and pilot-based CurveCV are univariate and cannot select this 2D bandwidth. :obs gives each pair weight one; :subj gives weight 1/(N_i*(N_i-1)). Every curve must have at least two observations. Stored data weights are unused. The supplied mean is interpolated at original observation times and held fixed through CV. Its grid must cover those times.

Optional integer binning >= 2 snaps times to the nearest of that many equally spaced points over the observed domain (midpoint ties go upward). Products still exclude only identical observation indices; multiplicities and original pair weights are retained. Pairs in each curve and bin cell are aggregated by summing weights and taking the weighted mean product. Within-cell squared errors are retained for raw-product CV scores. Residuals are computed before snapping.

surface stores the symmetric covariance and weights its trapezoidal grid weights. noise_variance estimates measurement error by integrating the smoothed raw squares minus the surface diagonal over the middle half of the work-grid domain, multiplying by 2/domain_length, and truncating at zero. By default (diagonal_bandwidth=nothing) the diagonal uses the covariance bandwidth, after any CV selection, as fdapace does; theory only requires the diagonal bandwidth to be of no larger order than the covariance bandwidth (Li and Hsing, 2010, Corollary 3.5). To choose it separately, pass a positive number, a CurveCV (including pilot-based candidates), or a regression KernelSmoothing.BandwidthSelector returning one global bandwidth; it is then selected independently of the covariance bandwidth. noise_details.diagonal_source is :covariance or :user. Diagonal CV predicts held-out raw squared residuals at their original times, leaving whole curves out with the mean CV fold and weighting rules. With binning, diagonal training times are snapped but held-out queries stay at original times. The supplied mean stays fixed. The diagonal uses local linear degree one and observation weights one or 1/N_i. Rules use pooled raw squared residuals, training times (snapped with binning), and the same observation weights. They assume independent observations, which is asymptotically adequate for sparse designs but ignores within-curve correlation in dense ones; use CurveCV for the final choice. Density-only and pointwise rules throw. noise_details.selection stores the rule, bandwidth, and selector details, or the CV candidates, errors, assignments, and pilot information when used. noise_details records its bandwidth, fold count, selection scores and assignments, raw estimate, truncation flag, integration bounds and grid, and fitted squares. Boundary values for integration are linearly interpolated. All settings and CV scores are retained and shown. No positive-semidefinite projection is made.

Automatic univariate pilots

Bandwidth keywords remain required. The pooled mean's bandwidth and the noise diagonal's diagonal_bandwidth also accept regression rules from KernelSmoothing, such as KernelSmoothing.RuleOfThumb() or KernelSmoothing.IMSEOptimal(). Each rule receives the smoother's pooled responses, times, observation weights, kernel, and degree. For the diagonal, responses are raw squared residuals and times are snapped when binning is used. The mean stores selection=(rule, bandwidth, details); the diagonal stores it in noise_details.selection. Density-only rules and rules returning pointwise vectors (currently MSEOptimal()) raise ArgumentError.

These rules assume independent observations. For sparse designs that is asymptotically adequate, because each curve contributes about one point to a smoothing window and the leading variance matches the independent case (Zhang and Wang, 2016, Corollaries 3.1 and 3.2). For dense designs they ignore the within-curve correlation term. Li and Hsing (2010, Section 4.1) also found IMSE-optimal bandwidths worked less well for $\sigma^2$ than slightly smaller ones. Treat these rules as pilots and use CurveCV, which leaves out whole curves and does not depend on the within-curve correlation, for the final choice. Theory requires only that the diagonal bandwidth be of no larger order than the covariance bandwidth (Li and Hsing, 2010, Corollary 3.5), so undersmoothing the diagonal is allowed.

pilot = KernelSmoothing.RuleOfThumb()
automatic = StatsAPI.fit(SmoothedMean, fd; grid=t, bandwidth=pilot)
cv = CurveCV(; pilot, folds=nobs(fd))
selected = StatsAPI.fit(SmoothedMean, fd; grid=t, bandwidth=cv)

Pilot-based CurveCV computes h_pilot on the full pooled data at fit time, then evaluates multipliers .* h_pilot with the existing curve-level CV. Defaults are multipliers=2.0 .^ range(-1, 2; length=10), folds=10, and rng=nothing; supply an RNG unless leaving one curve out. Selection retains pilot, h_pilot, pilot_details, copied multipliers, candidate bandwidths, CV errors, and fold assignments. Explicit CurveCV(bandwidths; ...) keeps its existing behavior. Both forms work for the mean and noise diagonal.

The covariance surface uses a bivariate smoother. KernelSmoothing rules are univariate, so covariance bandwidth rejects rules and pilot-based CurveCV. Use CurveCV with explicit candidates for that bandwidth.
