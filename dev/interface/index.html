Interface

The package implements grid, irregular, basis and multivariate functional data, smoothing, decompositions and uncertainty summaries. Curves are rows; components and evaluation points are columns where a matrix is returned.

Fitting and prediction

fit extends StatsAPI. Prefer project_scores for score-only projection and predict_scores for explicit score predictions with available uncertainty. Per-curve smoothers return functional data directly, while pooled smoothers return dedicated mean/covariance summaries and decompositions return model objects. The table records the current legacy StatsAPI.predict contracts, retained with deprecation warnings for FPCA, MultivariateFPCA and MFPCA. CCA variate prediction is unchanged. Here n is the new subject count, K a selected component count, and K_j the selected count for node j.

For raw univariate data, method=:auto selects dense FPCA for complete common-grid data and PACE for irregular or masked data. method=:face is explicit: grid input selects common-grid FACE; irregular input selects sparse FACE. It is not chosen automatically by sampling density. See FPCA, multivariate FPCA, cross-structure and CCA for route-specific settings and restrictions. Derivative results come from derivative(model, ...), rather than fit; they support reconstruction as described under derivatives.

ScorePrediction has named scores and covariances fields. It is not an array and does not implicitly discard uncertainty. nothing means no conditional score covariance is supplied; it does not assert zero uncertainty. Joint MFPCA does not assume independent node errors or propagate marginal covariances. PACE/FACE covariances retain their documented conditional interpretation and exclusions. All prediction arrays are newly computed and independent of training scores and input arrays. Modifying a result changes that result only. There is no new FSVD prediction algorithm, and CCA retains its separate (variates1, variates2) prediction contract.

Legacy StatsAPI.predict(model, data) keeps exactly its original matrix, named tuple, or vector of alternatives and warns for the three FPCA model types. Replace it explicitly with one of the two score APIs; no automatic return-type switch is implied for a later release. Input requirements and numerical calculations are shared with the legacy routes in the first table.

projected = project_scores(model, newdata)
prediction = predict_scores(model, newdata)
# prediction.scores is the matrix; prediction.covariances may be nothing.

Statistical accessors

StatsAPI.fitted(model) returns reconstruct(model) for FPCA, MultivariateFPCA and MFPCA: latent training curves on the stored work/display grids with training IDs, without added noise or parameter uncertainty. StatsAPI.residuals(model) subtracts those latent functions at the original observations, before presmoothing. Grid masks, irregular times/offsets, IDs, node order and exact basis representations are preserved. Grid/PACE/FACE residuals use the existing piecewise-linear reconstruction; basis residuals use exact coefficient arithmetic. Missing or imputed FACE values are not promoted to observed residuals. Both accessors return independent data.

StatsAPI.coef(data::BasisFunctionalData) returns the stored curve-by-basis coefficient matrix; copy it before mutation. There are no ambiguous model coef methods, and no fitted-observation or residual methods for FSVD, CCA or derivative summaries. Residuals contain truncation/smoothing error as well as noise and are not independent noise estimates.

FunctionalDataAnalysis.ScorePrediction — Type
ScorePrediction(scores, covariances)

Score prediction returned by predict_scores. scores is a subject × component matrix. covariances is a component × component × subject array, or nothing when this route supplies no conditional score covariance. nothing does not assert zero uncertainty. No array conversion or iteration implicitly discards uncertainty.

The constructor adopts its arrays. Predictions contain newly computed arrays independent of the fit and input data; use deepcopy for another independent result. The fields themselves expose the result's stored arrays.

FunctionalDataAnalysis.project_scores — Function
project_scores(model, newdata)

Return score matrices using the fitted mean, basis, preprocessing and score solver, without refitting. FPCA and joint MFPCA return n × K matrices; nodewise MultivariateFPCA returns a vector of n × K_j matrices in node order. Matrices are newly computed, independent of training scores and input arrays. Modifying them does not change the model.

Dense FPCA requires complete data on its training grid; basis FPCA requires its exact training basis. PACE and sparse FACE accept grid or irregular observations inside the work grid. Common-grid FACE requires its training grid and permits masks. Multivariate nodes follow these same restrictions. For conditional score covariance use predict_scores.

source
FunctionalDataAnalysis.predict_scores — Function
predict_scores(model, newdata)

Return a ScorePrediction, or a vector of these in node order for MultivariateFPCA. Its scores equal project_scores. PACE and both FACE routes supply their existing conditional score covariance arrays; dense/basis FPCA and joint MFPCA supply nothing. Joint MFPCA does not assume independent node errors or propagate marginal covariances into joint scores.

Conditional covariance excludes mean/covariance/noise estimation uncertainty; common-grid FACE's completed training data also exclude imputation uncertainty. The data restrictions are those of project_scores. Result arrays are newly computed and independent of the fit and input data.

StatsAPI.fitted — Method
fitted(model::Union{FPCA,MultivariateFPCA,MFPCA})

Return the latent training curves as reconstruct(model), with its existing functional-data type, work grids and IDs. The result owns its storage and contains no added observation noise or parameter uncertainty. No smoother is refitted. Exact-basis FPCA is evaluated exactly on its stored display grid. This extends StatsAPI.fitted; FSVD, CCA and derivative summaries have no fitted-observation method.

source
StatsAPI.residuals — Method
residuals(model::Union{FPCA,MultivariateFPCA,MFPCA})

Subtract the fitted latent training reconstruction from original stored observations, before any presmoothing. Return functional data with copied IDs and the original observation layout: grids and masks, irregular times and offsets, or exact basis coefficients. Multivariate results retain node order. Grid/PACE/FACE functions use the same piecewise-linear reconstruction as reconstruct, evaluated at actual observation times; exact-basis residuals retain the input basis. Missing points remain unobserved.

Results own their storage; modifying them does not change the fit. These residuals include observation noise and truncation/smoothing error and are not independent noise estimates. This extends StatsAPI.residuals; no residuals are invented for FSVD, CCA or derivative summaries.

source
StatsAPI.coef — Method
coef(fd::BasisFunctionalData)

Return the stored coefficient matrix, with curves in rows and input basis functions in columns. Mutating it changes the data; use copy for independent storage. This extends StatsAPI.coef. Decomposition scores, canonical weights and multivariate rotations are not exposed as ambiguous model coefficients.

Counts, orders and array inputs

Counts and orders must be integers other than Bool, representable as Int, within the argument's documented bounds. Zero remains valid for polynomial and derivative orders where documented; positive counts and minimum-two quantities retain their existing bounds. This includes component caps and counts, CCA counts, bootstrap replicates, curve folds, bin counts, basis sizes/orders, FACE intervals/degrees/difference orders and simulation counts. true and false are rejected even though Julia makes Bool <: Integer.

One-based array views and ranges are supported; offset-indexed inputs remain unsupported. Float32 smoke tests use relative tolerance 2e-3 and absolute tolerance 2e-5 against Float64 calculations, including fully estimated PACE and curve smoothing. These checks supplement the unchanged Float64 R contracts below 1e-8. KernelSmoothing currently computes curve-smoother matrices in Float64; the cache retains those operators and multiplication precision before converting output to the work-grid type. Float32 input/output support does not imply that every backend workspace uses Float32.

Generic ownership and storage

nobs, fit, predict, reconstruct, reconstruct!, fitted, residuals and coef are StatsAPI generics. StatsAPI 1.8 or newer is required for the shared reconstruct binding. Existing FDA reconstruction calls and return values are unchanged; qualified imports now identify the same generic:

import FunctionalDataAnalysis
import StatsAPI: fit, predict, reconstruct
# reconstruct(model) == FunctionalDataAnalysis.reconstruct(model)

evaluate and evaluate! remain owned by FunctionalDataAnalysis. When also loading MultivariateStats or another package exporting that name, use FunctionalDataAnalysis.evaluate(data, times) or import it explicitly. eigvals and svdvals extend LinearAlgebra's generics.

FSVD exposes svdvals, fve, left_functions, right_functions, left_scores, right_scores, nobs and ncomponents. CCA exposes canonical_weights, canonical_variates, canonical_correlations, squared_canonical_correlations, nobs and ncomponents. Array accessors return the fit's own storage; modifying that storage changes the fit. Use copy for arrays and deepcopy for basis-data weights. The CCA paired accessors return named tuples with left and right entries referencing the stored objects. Accessor docstrings give dimensions and ownership; CCA's penalized correlations generally differ from empirical correlations of its variates.

Reusing output buffers

evaluate! writes the numeric values of evaluate into a caller-owned matrix. reconstruct! similarly writes the values of the allocating functional-data result. The allocating APIs retain their existing ownership, IDs and metadata; numeric output buffers carry no IDs or metadata.

points = copy(data.grid)
values = similar(evaluate(data, points, PiecewiseLinear()))
evaluate!(values, data, points, PiecewiseLinear())

curves = similar(reconstruct(model).values)
reconstruct!(curves, model)

Use the exact element type of the allocating result, including promotion from points and supplied scores. A wrong shape throws DimensionMismatch; a wrong element type or possible overlap with input/model storage throws ArgumentError. Views with one-based indexing are supported. Aliasing checks are conservative: even disjoint views of one parent can be rejected by Base.mightalias. Node buffers must also be independent. Computation errors can leave partial output. Point/basis preparation and products into other layouts can still allocate; these functions guarantee reuse of output storage, not zero allocations.

Multivariate evaluation uses an nobs × ncomponents × npoints array for shared points, or a vector of matrices for node-specific point vectors. Multivariate reconstruction uses one matrix per node, including joint MFPCA and derivative summaries, with the same grid and score conventions as reconstruct.

FunctionalDataAnalysis.evaluate! — Function
evaluate!(out, fd, points[, evaluator]; derivative=0)

Write the values of evaluate into out and return that same buffer. For univariate data, out is an nobs(fd) × length(points) matrix. Raw grid or irregular data require PiecewiseLinear() or NoInterpolation(); basis data support the derivative keyword. Point order and repeated points are preserved, including the allocating evaluator's missing/extrapolation rules.

For multivariate data, common points require an nobs × ncomponents × npoints array. A vector of point vectors requires a vector of matrices in node order. An evaluator is required whenever a component is raw data, and ignored for basis components. These routes support value evaluation only.

Buffers must use one-based indexing and the exact floating element type of the allocating result, including its point-type promotion. Shape/type errors and conservative Base.mightalias checks reject overlap with input data, points or model storage, and overlap between node buffers, before writing. Evaluation errors can leave partial output. Inputs are never modified. Internal point/basis and noncontiguous-product workspaces can still allocate; this API reuses the caller's output storage.

StatsAPI.reconstruct! — Function
reconstruct!(out, model, projected=scores(model); grid=model.grid)
reconstruct!(node_buffers, model, projected=scores(model); grid=nothing)
reconstruct!(node_buffers, d::MultivariateFPCADerivative; grid=nothing)

Write the curve values of reconstruct into caller-owned buffers and return those buffers. This extends StatsAPI.reconstruct!, the in-place counterpart of the StatsAPI.reconstruct generic used by this package.

FPCA and FPCADerivative use a size(projected,1) × length(grid) matrix. MultivariateFPCA, MFPCA and MultivariateFPCADerivative use a vector of matrices, one per node, with the same grids/score conventions as their allocating methods. Values, arithmetic promotion and evaluation rules are identical. Buffers contain only numeric values; IDs and derivative metadata remain on the allocating functional-data results and are not attached to the buffers.

Each buffer must use one-based indexing and exactly the floating element type of its allocating result. Shape/type errors and conservative Base.mightalias checks reject overlap with scores, grids, model storage or other node buffers before writing. Computation errors can leave partial output. Inputs are never modified. Dense matrix products with matching input types write directly into the buffer; basis/mean preparation, mixed inputs and other layouts can still allocate workspaces. The allocating methods keep their existing ownership.

Data interface

FunctionalDataAnalysis.AbstractFunctionalData — Type
AbstractFunctionalData{T<:AbstractFloat}

A collection of n curves on a common domain, with floating-point type T. Concrete univariate types are GridFunctionalData, IrregularFunctionalData and BasisFunctionalData. MultivariateFunctionalData collects components for the same subjects. eltype(fd) is the numerical scalar type.

FunctionalDataAnalysis.evaluate — Function
evaluate(fd, t)

Evaluate each curve in fd at the points in t. Return an nobs(fd) × length(t) matrix, with curves in rows and evaluation points in columns.

Basis data evaluate exactly and accept derivative=0. Grid and irregular data require an explicit PiecewiseLinear() or NoInterpolation() evaluator. Piecewise-linear evaluation returns NaN outside a curve's observed range; exact lookup throws at any unobserved time. Query points must be finite.

This generic is owned by FunctionalDataAnalysis. Use FunctionalDataAnalysis.evaluate when also loading another package that exports evaluate, such as MultivariateStats.

Multivariate evaluation on a common point vector returns an nobs × ncomponents × length(t) array and rejects points outside any component's domain. A vector of point vectors returns one matrix per component. Pass an evaluator whenever any component is raw data; it is ignored for basis components.

source
FunctionalDataAnalysis.sampling_design — Function
sampling_design(fd)

Return :regular for complete grid data or basis data. For masked grids and irregular data, return :dense_irregular when the median observation count per curve is at least threshold (default 20), otherwise :sparse. The threshold must be finite and positive; an even sample uses the average of the two middle counts.

Multivariate data return a Vector{Symbol}, passing threshold to each component. For example, all(==(:regular), sampling_design(mfd)) checks that all components are regular; there is no aggregate multivariate design.

source
FunctionalDataAnalysis.quadrature_weights — Function
quadrature_weights(grid)

Trapezoidal integration weights on a finite, strictly increasing grid of at least two points. The weights sum to last(grid) - first(grid).

The result preserves the input's floating-point type. Integer grids produce Float64 weights. Invalid grids throw an ArgumentError.
