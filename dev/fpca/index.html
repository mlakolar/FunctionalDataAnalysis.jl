Functional principal component analysis

StatsAPI.fit(FPCA, data) estimates univariate functional principal components. With method=:auto, fully observed common-grid data use the dense route. Irregular and masked grid data use PACE, including designs classified as :dense_irregular. method=:pace also permits conditional-expectation scores for complete grid data. method=:dense requires complete common-grid data.

For GridFunctionalData, automatic routing depends on its observed-mask field at runtime, so inference includes both dense and PACE result types. Compiled callers that request a fixed method=:dense or method=:pace can infer that route's concrete result type. No-keyword irregular-data fits and the bandwidth candidate helper retain their inference checks.

using FunctionalDataAnalysis, Random, LinearAlgebra
import StatsAPI

grid = collect(range(0, 1; length=51))
simulation = simulate_kl(Xoshiro(42), 200;
    mean=t -> 1 + t,
    eigenfunctions=fourier_eigenfunctions((0, 1), 3),
    eigenvalues=[2.0, 0.5, 0.1], noise_sd=0,
    sampling=RegularSampling(grid))
model = StatsAPI.fit(FPCA, simulation.data)
(ncomponents(model), eigvals(model), fve(model))
(3, [1.9298367758650554, 0.46521563862761356, 0.10679975551471375], [0.7713632320087722, 0.9573117241717768, 1.0])

The fit retains the sample mean, unprojected sample covariance, training scores, eigenfunctions, and the component-selection record. Dense covariance uses the denominator n - 1. Scores use the stored trapezoidal quadrature weights. Their sample covariance has the selected eigenvalues on its diagonal. The noise_variance and score_covariances accessors return nothing for a dense fit.

projected = StatsAPI.predict(model, simulation.data)
restored = reconstruct(model)
(size(projected), size(restored.values), model.selection)
((200, 3), (200, 51), (rule = :FVE, threshold = 0.99, maxK = 49, chosen = 3, scores = [0.7713632320087722, 0.9573117241717768, 1.0]))

New dense curves must use exactly the training grid. Reconstruction evaluates the training mean and the piecewise-linear eigenfunctions on the requested grid, which must lie inside the training domain. The default reconstruction uses the training scores and preserves subject IDs. Other score matrices do not inherit training IDs.

scores(model) returns the fit's own score matrix. Mutating it changes the fit and subsequent reconstruction. Use copy(scores(model)) for independent storage; reconstructing from that copy does not inherit training IDs.

Prediction applies the training presmoothing settings. When spline GCV selected a penalty, prediction uses that selected penalty for new curves.

Defaults and where they come from

Let n = nobs(data), g = length(model.grid), and r be the range of the observed times. The defaults below are resolved and recorded when fitting. The source audit uses fdapace 0.6.0; its executable defaults differ from some older help text. See Comparison with fdapace for details.

All tuning settings are stored on the fit and displayed by show. The selection record stores the rule, FVE threshold when applicable, maxK, chosen component count, and rule scores. all_eigenvalues and fve(model) refer to every retained positive eigenvalue up to maxK, before component selection. Negative eigenvalues are removed before selection. Their count, absolute total, and share of the absolute spectrum are recorded in dropped. Values at or below the positive relative tolerance are excluded from the FVE denominator.

For noisy dense observations, pass a LocalPolynomial or PenalizedSpline object as presmooth, or use method=:pace. Presmoothing calls smooth_curves on the data grid. The fit retains the smoothing settings and any tuning-selection metadata.

The implementation resolves these details left unspecified by the milestone:

  • A zero retained positive rank raises ArgumentError; FPCBasis requires at least one function. The default cap is clamped to one for two curves or two grid points, following fdapace.
  • The dense mean is stored as a one-curve GridFunctionalData; the unprojected covariance is stored as a matrix. Presmoothing metadata retains the selected GCV penalty, which is fixed for prediction.
  • Sign ties use the first largest absolute entry. The numerical tolerances are the adjustable package choices listed above.
  • Reconstruction preserves IDs when the score object is the training score matrix. A copied or different score matrix has no inferred IDs.

PACE for sparse observations

PACE estimates a pooled mean and latent covariance, then predicts each subject's principal component scores by conditional expectation. It reuses SmoothedMean and SmoothedCovariance. A no-keyword fit uses the work grid, Gaussian kernel, and fractional bandwidths listed above. The Gaussian avoids empty windows caused by compact support, but it cannot prevent ill-conditioned local fits on extremely coarse or clustered data. Such fits raise an informative error suggesting a larger bandwidth. Increase mean_bandwidth or covariance_bandwidth explicitly when needed; the fit does not enlarge them automatically.

using FunctionalDataAnalysis, Random, LinearAlgebra
import StatsAPI

simulation = simulate_kl(Xoshiro(43), 120;
    mean=t -> 1 + t,
    eigenfunctions=legendre_eigenfunctions((0, 1), 2),
    eigenvalues=[1.5, 0.4], noise_sd=0.3,
    sampling=SparseSampling((0, 1), 3:8))
model = StatsAPI.fit(FPCA, simulation.data)
(ncomponents(model), size(scores(model)), size(score_covariances(model)))
(3, (120, 3), (3, 3, 120))

This fit estimates the noise variance with SmoothedCovariance's rotated, full-interval default. Singular rotated windows throw an informative error; increase the covariance bandwidth or supply a SmoothedCovariance fitted with noise_method=:surface_diagonal for a small design. Pass noise_variance=0.09 to use the simulation's known value. Smoother settings, selection metadata, the origin of every supplied or estimated input, and the noise truncation details are retained on the fit. Inputs are copied.

Let $\widetilde G$ denote the positive-semidefinite projection of the work-grid surface over all positive components retained up to maxK. Negative eigenvalues are dropped and reported in model.dropped. The selected component count $K$ can be smaller than this retained rank. At subject $i$'s observed times, let $\Phi_i$ contain the selected eigenfunctions and $\Lambda=\operatorname{diag}(\lambda_1,\ldots,\lambda_K)$. The scores and their conditional covariance are

\[\begin{aligned} \Sigma_i &= \widetilde G(t_i,t_i)+\sigma^2 I,\\ \widehat\xi_i &= \Lambda\Phi_i^\mathsf T\Sigma_i^{-1}(y_i-\mu_i),\\ \Omega_i &= \Lambda-\Lambda\Phi_i^\mathsf T\Sigma_i^{-1}\Phi_i\Lambda. \end{aligned}\]

The denominator $\Sigma_i$ uses the full retained projected covariance, including components beyond the selected $K$. This is the observed-curve covariance in Yao, Müller, and Wang (2005) and fdapace. The numerator and $\Omega_i$ use the selected components. Mean and eigenfunction evaluation are linear; covariance evaluation is bilinear. The systems are solved by Cholesky factorization. A non-positive-definite system raises an error naming the curve and suggesting an explicit noise_variance. No ridge, noise floor, or pseudoinverse is added.

score_covariances(model) is a K × K × n array: slice [:, :, i] is $\Omega_i$. Under the Gaussian model, it measures remaining uncertainty about the latent scores after observing curve $i$. It is not the sample covariance of the predicted scores. Use it when propagating score uncertainty to reconstructions or downstream inference; sparse-curve scores can have substantial shrinkage and uncertainty. These covariances condition on the fitted mean, covariance, and noise variance, so they do not include uncertainty from estimating those quantities.

new_scores, new_covariances = StatsAPI.predict(model, simulation.data[1:3])
restored = reconstruct(model)
(size(new_scores), size(new_covariances), size(restored.values))
((3, 3), (3, 3, 3), (120, 51))

PACE prediction accepts grid or irregular data and returns (scores, covariances). It uses the training mean, eigenfunctions, projected covariance, and noise variance. Every observation time must lie inside the work-grid domain. Prediction on the training data agrees with the stored scores and conditional covariances. Reconstruction uses the same interface as dense FPCA and preserves training IDs.

Supplied means, surfaces, and noise variance

Supply mean=smoothed_mean to reuse a SmoothedMean, or mean=(; grid, values) for an explicit mean curve. The mean grid must cover the entire work grid and every observation time. Supply covariance=smoothed_covariance to reuse a SmoothedCovariance, or covariance=(; grid, surface) for a finite symmetric covariance surface. Surfaces that are asymmetric only by rounding (relative tolerance sqrt(eps), as R's isSymmetric allows) are accepted and replaced by (S + S')/2. The surface grid must cover the work grid. A supplied surface requires an explicit nonnegative noise_variance. Supplied objects are copied with their settings; they are not refitted.

The fit stores its work-grid mean as one-curve GridFunctionalData and its unprojected work-grid covariance as a matrix. settings.mean_input and settings.covariance_input retain copied supplied or estimated inputs; settings.full_projected_covariance retains the surface used for scores and prediction. Mean, covariance, and noise provenance are recorded separately. Noise inherited from a SmoothedCovariance retains :estimated provenance, including when that covariance object was supplied to the fit.

If the covariance must be estimated, the mean must be estimated in the same fit or supplied as a SmoothedMean. A named-tuple mean cannot be passed to the existing pooled covariance smoother; supply a covariance surface with that mean instead. Bandwidth defaults are used only for the respective estimated inputs. Supplying mean_bandwidth together with a supplied mean raises ArgumentError. Supplying covariance_bandwidth or diagonal_bandwidth together with a supplied covariance also raises ArgumentError. Reused inputs retain their fitted tuning values; unused bandwidth overrides are rejected.

Binning only affects covariance estimation. With a supplied covariance, binning must remain :auto, and the fit records settings.binning=nothing and settings.binning_rule=:not_applicable. When both mean and covariance are supplied, kernel must remain nothing and weighting must remain :obs; overrides raise ArgumentError. Their active settings are recorded as nothing because no smoother runs. If either input is estimated, kernel and weighting still tune that smoother. Supplied fitted inputs keep their original settings under settings.mean_input and settings.covariance_input.

Overriding defaults and selecting bandwidths

Every automatic choice can be replaced explicitly. For example:

import KernelSmoothing

model = StatsAPI.fit(FPCA, simulation.data;
    method=:pace,
    grid=collect(range(extrema(simulation.data.times)...; length=61)),
    ncomponents=2, maxK=6,
    kernel=KernelSmoothing.GaussianKernel(), weighting=:subj,
    mean_bandwidth=0.15, covariance_bandwidth=0.25,
    diagonal_bandwidth=0.20, binning=nothing)

For an irregular object, use extrema(simulation.data.times) to obtain the observed endpoints: concatenated times are ordered within curves, rather than across curves. A work grid may cover a wider interval, but all observations must remain inside it. Fractional bandwidth defaults always use the observed time range, not the work-grid range.

pace_bandwidth_candidates returns the ten geometric mean and covariance bandwidths from fdapace's GCVLwls1D1 and GCVLwls2DV2 candidate grids. The candidate values use the Gaussian convention of the PACE default. Pass kernel=KernelSmoothing.EpanechnikovKernel() to generate the compact-kernel variant, and use the same kernel for fit. The helper does not run fdapace's GCV, choose a bandwidth, or fit a smoother. Use whole-curve CV to select from these candidates:

candidates = pace_bandwidth_candidates(simulation.data)
model = StatsAPI.fit(FPCA, simulation.data;
    mean_bandwidth=CurveCV(candidates.mean; folds=10, rng=Xoshiro(44)),
    covariance_bandwidth=CurveCV(candidates.covariance; folds=10, rng=Xoshiro(45)))

Pass grid=work_grid to both the helper and fit when using a custom work grid. CurveCV retains the candidate grid, errors, and fold assignments. Mean selectors and covariance selectors pass to the existing pooled smoothers unchanged. The 2D covariance smoother accepts a number or explicit CurveCV candidates; KernelSmoothing bandwidth selectors are univariate. Covariance CV holds the supplied fitted mean fixed across folds. It holds out whole curves, whereas fdapace's covariance CV holds out raw covariance pairs. These procedures therefore need not select the same bandwidth. The helper requires enough unique observation times and time pairs for the audited nearest-neighbor starts. It throws if they are unavailable. Equal candidate endpoints can yield repeated values; use unique(candidates.mean) or unique(candidates.covariance) before CurveCV in that case.

Cost and automatic binning

Let N_i be the number of observations on curve i, M=sum(N_i), P=sum(N_i*(N_i-1)), and g the work-grid size. Fixed-bandwidth pooled mean smoothing costs O(g*M); unbinned covariance smoothing costs O(g^2*P) after forming P off-diagonal products. The weighted eigenstep costs O(g^3) and the per-curve Cholesky score solves cost O(sum(N_i^3)). The defaults perform no bandwidth search.

For binning=:auto, take m=median(N_i) for sparse designs and m=max(N_i) otherwise, as in fdapace's audited rule:

  1. With m<=20, do not bin.
  2. With m>400, initially choose 400 bins.
  3. With n>5000, compute mstar=max(20,400+19*(5000-n)/2250) and choose ceil(mstar) bins if mstar<m; otherwise do not bin.
  4. If none of these rules selects a count, do not bin.

The candidate helper and bin-count decision use fdapace's IsRegular classification. Let u be the number of unique pooled observation times and coverage=M/(n*u). Full coverage is Dense with at least eight unique times and Sparse with fewer than eight. Incomplete coverage above 0.8 is DenseWithMV; other designs are Sparse. This classifier controls only the mean-candidate start and bin-count statistic. It does not change FPCA's :auto route: complete GridFunctionalData use dense FPCA, and irregular or masked data use PACE.

The resolved bin count and the decision's design, count statistic, summary count, and number of curves are stored and shown. Binning snaps covariance-pool times and combines within-curve cell products with their original weights; it does not discard observations. It uses the existing covariance smoother, rather than fdapace's separate preprocessing of each curve. The pooled mean and work-grid length are unchanged by this aggregation. With b bins, Q=sum(min(N_i*(N_i-1),b^2)) bounds its occupied cells. Covariance smoothing then costs O(g^2*Q), and pair storage costs O(Q), after O(P) work to form the products. Most sparse curves have at most 20 observations, so automatic binning does not turn on, even when n is large.

The candidate helper's covariance nearest-neighbor calculation itself takes O(U^2) time and O(U) storage for U unique time pairs, including diagonal pairs. It is optional and is not run by a default fit.

A 2D CurveCV with H candidate bandwidths and F folds costs O(H*P^2 + H*F*P) without binning, or O(H*Q^2 + H*F*Q) with binning. The held-out products are evaluated at their pool coordinates (snapped when binning is enabled), rather than only at the work grid. Ten candidate bandwidths can therefore cost much more than a fixed-bandwidth fit. Reduce the candidate set or set an explicit bin count when that expense is inappropriate. See Smoothing for the weight-preserving binning and CV contracts.

PACE component selection

Missing mean and covariance inputs estimate the pooled smoothers, following Yao, Müller, and Wang (2005). Missing noise_variance uses SmoothedCovariance's nonnegative estimate; a supplied surface requires an explicit number. The score solve uses unregularized conditional expectation and must admit Cholesky factorization. Eigenanalysis, signs, and numerical tolerances are shared with the dense route.

For AIC() and BIC(), each candidate $k$ uses its own $k$-component covariance plus $\sigma^2 I$ in the Gaussian likelihood. The criterion is minus twice the log likelihood plus $2k$ or $k\log(n)$, respectively. selection.scores stores the full criterion curve for k=1:maxK; selection.candidates records those counts. When maxK exceeds the retained positive rank, the additional components have zero variance, leave the likelihood unchanged, and increase only the penalty. Selection stops at the first increase, following fdapace. The chosen count and selection.global_minimizer are both recorded, so a later lower value remains visible. The Gaussian normalization constant is included; fdapace omits it, which does not affect either selected count.

The analytic tests check the conditional-expectation formulas, including the full-covariance denominator. A separate 3000-curve sparse Gaussian simulation uses known mean, covariance, and noise with 3 to 8 points per curve. Mean squared score error is compared with the mean trace of $\Omega_i$ within 10%, and each standardized component error variance is checked within 10% of one. These are Monte Carlo checks, not coverage guarantees after smoothing.

Default recovery checks and their limits

A fixed-seed simulate_kl check uses 400 sparse curves, 2–6 observations per curve, Fourier constant/sine components with eigenvalues [2.0,0.7], and noise variance 1.0. A no-keyword fit has weighted mean L2 error below 0.30, sign-invariant weighted L2 error below 0.35 for each of the first two eigenfunctions, and noise relative error below 0.40. An 80-curve, 25-point regular-grid check compares dense and PACE eigenvalues within 15% and absolute weighted eigenfunction correlations above 0.98.

These thresholds describe finite simulations. They are not universal recovery guarantees. A historical lower-noise diagnostic with the same sparse signal and true variance 0.25 estimated 0.56615 under the former surface-diagonal, middle-half default. That value does not describe the current rotated, full-interval default, chosen using the Discovery results. The fixed 0.10r covariance bandwidth can leave appreciable smoothing bias. Inspect the fitted noise estimate and use an explicit bandwidth selector or known noise_variance when appropriate.

Basis and numerical conventions

eigenfunctions(model) is an FPCBasis. Its columns are orthonormal under the stored work-grid quadrature weights. Evaluation between work-grid points uses linear interpolation. Evaluation outside the domain throws. gram(basis) instead integrates the products of those piecewise-linear interpolants exactly. It is generally close to, but not exactly, the identity. Derivative evaluation and positive-order roughness penalties are unsupported.

The weighted eigenproblem is sqrt(W) * covariance * sqrt(W), where W=Diagonal(weights). Dividing its eigenvectors by sqrt.(weights) gives work-grid eigenfunctions. See Comparison with fdapace for source-level details and the explicit compatibility convention used by the R golden tests. Spectrum sums and sign comparisons are evaluated after rescaling to avoid overflow while preserving the stated FVE and relative sign rules.

The dense covariance denominator differs from the n denominator in the FunctionalGraphicalModels.jl reference. The multivariate comparison below accounts for this convention explicitly.

Multivariate FPCA

StatsAPI.fit(FPCA, mfd::MultivariateFunctionalData) returns a MultivariateFPCA. The default basis=:marginal fits each node with the univariate method above. Nodes may use different grids or mix complete grid data with sparse irregular data. Each node retains its own route, defaults, tuning record, and conditional score covariances, when applicable. This operation performs separate marginal decompositions. The joint multivariate decomposition of Happ and Greven is a later milestone 4 task.

model = StatsAPI.fit(FPCA, mfd; basis=:marginal, ncomponents=2)
node_model = component(model, 1)
node_scores = scores(model, 1)
counts = ncomponents(model) # one selected count per node

For marginal fitting, every univariate keyword accepts either a shared value or a length-p vector containing one value per node. A numeric work grid is one shared grid; an outer vector of grids or nothing entries specifies one choice per node. To supply different means or covariance surfaces, use a vector of the same fitted objects or named tuples accepted by univariate FPCA. A vector with the wrong node count throws. For example:

model = StatsAPI.fit(FPCA, mfd;
    basis=:marginal, ncomponents=[2, 3], maxK=[4, 5],
    grid=[work_grid_node_1, work_grid_node_2])

The basis=:pooled route estimates one common basis from the average of the node sample covariance matrices. It follows the partial-separability construction of Zapata, Oh, and Petersen (2022). Every node must be complete GridFunctionalData on exactly the same grid. Masked grids, irregular nodes, and mismatched grids throw. Pooled PACE is not implemented.

For centered node matrices $Z_j=X_j-\mathbf 1\widehat\mu_j^\mathsf T$, the pooled surface and node scores are

\[\widehat G_{\mathrm{pool}} =\frac1p\sum_{j=1}^p\frac{Z_j^\mathsf T Z_j}{n-1}, \qquad \widehat\xi_{ijm} =\sum_g w_g\{X_{ij}(t_g)-\widehat\mu_j(t_g)\}\widehat\phi_m(t_g).\]

The weighted eigenstep and positive-eigenvalue cutoff are the same as for univariate FPCA. ncomponents is an integer or FVE(threshold), defaulting to FVE(0.99); maxK follows the dense route. Selection uses the pooled spectrum. The sign rule uses the average of the node mean curves as its common reference and records sign_reference=:average_node_mean. Near-zero overlap uses the same largest-absolute-entry fallback as univariate FPCA. The pooled tuning keywords are ncomponents, maxK, eigen_tol, and sign_tol; method=:auto or :dense is accepted. Pooled presmoothing, custom work grids, and PACE smoothing options throw because no corresponding pooled method is implemented. Each node keeps its own sample mean, and eigvals(model)[j] reports that node's score sample variances, with denominator n-1. These node variances need not be ordered within a node because the shared basis is ordered by the pooled spectrum. eigenfunctions(model) returns the shared FPCBasis for every node. component(model, j) throws for a pooled fit because there is no separately fitted univariate FPCA at that node.

pooled = StatsAPI.fit(FPCA, mfd; basis=:pooled, ncomponents=2)
array = score_array(pooled) # subjects × nodes × principal components

score_array gives FunctionalGraphicalModels.jl's n × p × M convention. Its node order is exactly the order of component(mfd, j) and the second axis of to_array(mfd). It requires equal selected counts across nodes. Unequal counts throw and suggest an integer ncomponents; scores are never padded or truncated. scores(model) always returns a vector of node score matrices. These matrices are the fit's own storage; copy them before independent mutation. score_covariances(model) returns a vector whose entries are conditional covariance arrays for PACE nodes and nothing for dense or pooled nodes.

StatsAPI.predict(model, newmfd) returns one prediction per node using the training means and bases. Dense predictions are score matrices; PACE predictions are the univariate (scores, covariances) named tuples. reconstruct(model) returns MultivariateFunctionalData and preserves training subject IDs. Its grid keyword accepts one shared grid or one grid per node; without an override, each training grid is used. Reconstruction from other score matrices follows the univariate ID convention above.

The FunctionalGraphicalModels.jl reference computes dense covariance and score variances with denominator n. FDA uses n-1, so matching eigenvalues are the reference values multiplied by n/(n-1). Dense scores retain their scale. Reference dense eigenfunction signs must be aligned before comparing scores. See Milestone 4 comparison report for the frozen reference, sparse-route differences and defaults.

Cross-covariances arrive in a later milestone 4 task. Smoothed FPCA with a roughness penalty, FACE, and fdapace's conditional-score rho regularization are not yet implemented. Presmoothing individual curves does not implement a roughness penalty on the FPCA eigenfunctions.

FunctionalDataAnalysis.FPCA — Type
fit(FPCA, fd; method=:auto, grid=nothing, ncomponents=FVE(0.99),
    maxK=nothing, presmooth=nothing, mean=nothing, covariance=nothing,
    noise_variance=nothing, mean_bandwidth=nothing,
    covariance_bandwidth=nothing, diagonal_bandwidth=nothing, kernel=nothing,
    weighting=:obs, binning=:auto, eigen_tol=1e-10, sign_tol=1e-12)

Univariate functional principal component analysis. Complete grid data use the dense route: cross-sectional mean and sample covariance with denominator n-1 (R's cov, also used by fdapace 0.6.0 GetCovDense). :auto chooses this route for sampling_design(fd) == :regular; irregular or masked data use PACE. method=:pace forces PACE on either data representation, while method=:dense requires complete GridFunctionalData. Pooled smoothing keywords are accepted only on the PACE route.

PACE implements the conditional-expectation method of Yao, Müller, and Wang (2005). Its work grid defaults to 51 equally spaced points over the observed time range (fdapace 0.6.0 nRegGrid, SetOptions.R). An override must cover every observation time. A missing mean estimates SmoothedMean; a supplied SmoothedMean must have derivative=0 and is copied, or supply (; grid, values) for a linearly interpolated mean. Its grid must cover the work grid and every observation. A missing covariance estimates SmoothedCovariance, using an estimated or supplied SmoothedMean. Alternatively supply that fitted type or a symmetric (; grid, surface) for bilinear interpolation. noise_variance=nothing uses the covariance smoother's stored nonnegative estimate; a supplied surface requires a finite nonnegative override. Supplying a fitted mean together with mean_bandwidth, or a covariance with covariance_bandwidth or diagonal_bandwidth, throws rather than ignoring the requested tuning of an input that is not refitted. With a supplied covariance, binning must remain :auto; the fit records binning=nothing and binning_rule=:not_applicable. When both inputs are supplied, kernel must remain nothing and weighting must remain :obs; their active settings are recorded as nothing because no smoother runs. Supplied fitted inputs retain their original smoothing settings.

PACE uses local linear degree one (Yao, Müller, and Wang, 2005). kernel=nothing resolves to Gaussian, and weighting=:obs follows fdapace 0.6.0 SetOptions.R; :subj is also available (neither scheme uniformly dominates: Zhang and Wang, 2016, doi:10.1214/16-AOS1446). The standalone smoothers retain Epanechnikov. mean_bandwidth=nothing and covariance_bandwidth=nothing resolve respectively to 0.05 and 0.10 times the observed time range (fdapace methodBwMu="Default", methodBwCov="Default"). Explicit numbers, CurveCV, and mean KernelSmoothing selectors pass unchanged to the existing smoothers. diagonal_bandwidth=nothing uses the selected covariance bandwidth, following fdapace and milestone 2; override it with a number or univariate selector. pace_bandwidth_candidates supplies fdapace's optional candidate grids.

binning=:auto follows fdapace GetBinNum: use the median curve count for fdapace's Sparse classification and the maximum otherwise. Classification uses IsRegular's pooled observed-time coverage, as described in pace_bandwidth_candidates, independently of the FPCA route. Counts at most 20 never bin; counts above 400 initially use 400 bins. If n>5000, set mstar=max(20,400+19*(5000-n)/2250) and use ceil(mstar) bins only when the unrounded mstar is below the count. Otherwise no bins are selected. Override with nothing or an integer >=2. The selected count is passed to the existing covariance smoother, which preserves raw pair weights and snaps covariance/diagonal training times; the mean and output grid are unchanged. This differs from fdapace's raw-curve averaging and possible output-grid reduction. Both the request and resolved count are stored. With P=sum(N_i*(N_i-1)) pairs and M=length(grid), fixed covariance smoothing costs O(M^2*P) time. A 2D CurveCV with H candidates costs O(H*P^2 + H*F*P) for F folds, before the final fit; binning reduces P to the number of occupied per-curve cells (at most n*binning^2). maxK=nothing resolves to max(1,min(20,length(grid)-2,nobs(fd)-2)) for PACE, following fdapace 0.6.0's smoothed route. An explicit PACE cap may be at most length(grid).

The full positive-semidefinite covariance projection up to maxK is used in each curve's Cholesky score solve. The selected eigenvalues and eigenfunctions define the score numerator and conditional covariance. PACE also supports AIC and BIC. Their criteria use the K-component covariance, including the Gaussian normalization constant, for every candidate K=1:maxK. Beyond the retained positive rank the covariance has zero additional variance, while the penalty still increases. Selection stops at the first increase as fdapace does; the global minimizer is retained too. No noise floor or ridge is added. A non-positive-definite observation covariance throws with the curve index and a suggestion to supply noise_variance.

The eigensystem of sqrt(W)*G*sqrt(W) uses the data's stored trapezoidal weights, including on nonuniform grids. Eigenvalues must exceed eigen_tol times the largest absolute eigenvalue. The relative cutoff 1e-10 is a package numerical choice, adjustable here. All negative eigenvalues, including roundoff, are recorded in dropped as their number, absolute total, and share of the absolute spectrum. Positive eigenvalues up to maxK define the FVE denominator. ncomponents is a positive integer or FVE; the default threshold 0.99 is fdapace's. The default maxK=max(1, min(length(fd.grid)-2, nobs(fd)-2)) follows fdapace 0.6.0's dense cross-sectional default (SetOptions.R), without the cap of 20 used on its smoothing route. An explicit dense maxK cannot exceed min(length(fd.grid), nobs(fd)-1). A fixed K exceeding maxK or the retained positive rank throws. A zero-variance sample also throws.

Signs make sum(phi .* mean) nonnegative, following fdapace. When its magnitude is at most sign_tol * norm(phi) * norm(mean), the largest absolute entry is made positive, with the first entry breaking ties. The relative tolerance 1e-12 is an adjustable package numerical choice; the fallback follows FunctionalGraphicalModels.jl. Orthonormality is under work-grid weights.

presmooth=nothing assumes negligible measurement noise, as in Ramsay and Silverman (2005), chapter 8. Noisy dense data should use presmooth or method=:pace. A LocalPolynomial or PenalizedSpline is applied through smooth_curves, evaluated on the original data grid, and recorded with its selected tuning metadata. Prediction applies the same fitted preprocessing; a spline GCV choice is fixed at its training-selected lambda. All choices are stored and shown. training_data retains a copy of the original observations (before presmoothing) for fitted_curve_data. Inputs are copied. Dense noise variance and score covariances are nothing.

FPCBasis(grid, values; weights=quadrature_weights(grid))

Principal component functions stored in the columns of a length(grid) × K matrix. The grid, function values and quadrature weights are copied. The grid must be finite and strictly increasing, with at least two points. At least one function is required; values must be finite and weights must be finite, positive and have the same length as the grid.

basismatrix evaluates the piecewise-linear interpolants inside the closed grid range and throws outside it. Only derivative zero is supported; penalty likewise supports only order zero. gram gives exact integrals of products of the piecewise-linear interpolants.

Functions produced by fit(FPCA, ...) are orthonormal under the stored work-grid trapezoidal weights. Their exact interpolant Gram matrix is close to, but generally not exactly, the identity on a sufficiently fine grid. The constructor does not normalize arbitrary supplied function values.

FunctionalDataAnalysis.pace_bandwidth_candidates — Function
pace_bandwidth_candidates(fd; grid=nothing, kernel=KernelSmoothing.GaussianKernel())

Return (mean, covariance) vectors of ten geometric bandwidth candidates from fdapace 0.6.0's GCVLwls1D1 and GCVLwls2DV2 (local linear degree one). grid=nothing uses 51 equally spaced points over the observed range, as in FPCA; a supplied grid must cover every observation. The covariance range is sqrt(2) times the observed range, as in fdapace, and its starting bandwidth is multiplied by 0.2 for the default Gaussian kernel. Supply the same kernel to this helper and the fit when overriding that default.

The mean start uses the largest lag-three unique-time gap for fdapace's Sparse classification, twice the lag-two gap for DenseWithMV, and 1.5 times the lag-two gap for Dense. Its IsRegular classification uses coverage of the pooled time union: full coverage with at least eight unique times is Dense; full coverage with fewer times is Sparse; otherwise coverage above 80% is DenseWithMV, and lower coverage is Sparse. This does not change FPCA's route. The sparse start is multiplied by 2.5, after reducing its gap by 0.75 if larger than a quarter of the observed range. The covariance start is the worst distance to three other unique within-curve time pairs, including diagonal pairs, measured in the maximum coordinate norm (BwNN). Insufficient unique times or pairs throw. Equal endpoints return repeated candidates exactly as fdapace does; use unique before constructing CurveCV in that degenerate case.

This constructs candidates only: CurveCV holds out whole curves, whereas fdapace covariance GCV/CV uses different losses and raw-pair folds. For example, mean_bandwidth=CurveCV(pace_bandwidth_candidates(fd).mean; folds=nobs(fd)) requests leave-one-curve-out selection. Covariance candidates cost O(P^2) time and O(P) memory for P unique time pairs. A covariance CurveCV with H candidates costs O(H*P^2) plus O(H*F*P) fold setup for F folds; it can be much more expensive than a fixed-bandwidth fit.

FunctionalDataAnalysis.MultivariateFPCA — Type
MultivariateFPCA
fit(FPCA, mfd::MultivariateFunctionalData; basis=:marginal, kwargs...)

Multivariate FPCA with one fit per node (basis=:marginal, the package's default for nodewise analysis) or one shared basis (basis=:pooled). Marginal fits delegate to univariate FPCA, including its dense/PACE routing and all defaults. Each keyword can be shared or an AbstractVector of one value per node. A flat real grid vector is a shared work grid; use a vector of grids (or nothing) for per-node grids. Supplied means and covariances use the same fitted-object or named-tuple forms as univariate FPCA. Wrong vector lengths throw DimensionMismatch.

Pooled fits retain copied original observations in training_data for nodewise derivative covariance and score estimation. Marginal fits retain observations in their individual univariate fits.

Pooled FPCA requires complete grid data on the same grid; pooled PACE is not implemented. It averages node sample covariances with denominator n-1, then reuses the weighted univariate eigenstep. Each node is centered by its own mean. Node eigenvalues are score sample variances with denominator n-1, ordered by the shared pooled spectrum, rather than necessarily decreasing. The pooled spectrum, selection, dropped spectrum, sign rule, and settings are stored in f.pooled. The sign reference is the average node mean; the univariate largest-entry fallback resolves near-zero alignment.

Pooled defaults ncomponents=FVE(0.99), maxK=nothing, eigen_tol=1e-10, and sign_tol=1e-12 follow the dense univariate defaults and have the sources given in FPCA. The pooled covariance averages p node covariances of rank at most nobs-1, so its rank is at most p*(nobs-1); maxK therefore resolves to max(1,min(grid_length-2,p*(nobs-1)-1)), the dense rule with that rank, with explicit cap min(grid_length,p*(nobs-1)). Only shared values of these four keywords and method=:auto/:dense are supported for pooled fits. PACE tuning and presmooth throw instead of being ignored. Inputs and settings are copied.

The covariance averaging follows partial separability in Zapata, Oh and Petersen (2022), doi:10.1093/biomet/asab046. score_array supplies FunctionalGraphicalModels.jl's subject × node × component ordering. That package's reference covariance divisor is n, so its dense eigenvalues must be multiplied by n/(n-1) for comparison.

Derivatives

derivative(model) estimates velocity curves from a fitted FPCA. It returns an FPCADerivative with a mean derivative, derivative functions on the stored work grid, scores, bandwidths, kernel, and all choices. reconstruct(d) returns functional data; curve_data(d) and plot(d) draw the reconstructed derivative curves. mean_data(d) returns the mean derivative. These operations do not refit the model.

velocity_fit = derivative(model; mean_bandwidth=0.08,
    covariance_bandwidth=0.10)
velocity_curves = reconstruct(velocity_fit)
velocity_mean = mean_data(velocity_fit)
# With Plots loaded:
# plot(velocity_fit; curves=1:3)

The default method=:FPC differentiates the stored mean and each selected eigenfunction by local polynomial fitting, then combines them with the original scores. Orders one and two are supported. Derivative functions need not be orthogonal, and the retained eigenvalues describe the original curves. The default degree equals the derivative order, matching fdapace 0.6.0 FPCAder; this differs from the ν+1 default for standalone polynomial derivatives. fdapace labels second derivatives experimental. Accuracy still depends on the work-grid resolution, bandwidth, and smoothness of the fitted functions.

method=:DPC (Dai, Müller and Tao, 2018) instead estimates principal components of the derivative process, with its own eigenvalues and scores. It supports first derivatives and defaults to degree two and FVE(0.9999). Pass an integer or FVE via ncomponents to change that choice. It applies the polynomial derivative operator in both arguments of the covariance and reuses the usual weighted eigenstep. Dense fits use the sample covariance and project the correspondingly differentiated centered training curves. PACE uses the full projected covariance and conditional-expectation scores from the original observations. The curve/derivative-score cross-covariance supplies the CE numerator. No noise ridge is introduced. Conditional score covariances omit uncertainty from fitting mean, covariance, and noise.

DPC here uses stored quadrature weights, including nonuniform grids, and the same differentiated covariance for its derivative eigenvalues and score prior. fdapace's native DPC mixes finite differences, polynomial smoothing, rectangular quadrature, and an unsmoothed score-prior spectrum. Its DPC mean is also re-estimated from raw observations, whereas this package differentiates the fitted mean supplied by the user. The fdapace audit describes the resulting reference quantities and their validation. FPC1 is not implemented.

For either method the default kernel is Gaussian. With derivative order ν and domain width r, both default bandwidths are ν*0.10r when the fitted noise variance divided by the sum of selected original eigenvalues is at least 0.01, and ν*0.05r otherwise (including dense fits without a noise estimate). These rules follow fdapace 0.6.0 SetDerOptions. Supply a common bandwidth, or both mean_bandwidth and covariance_bandwidth. A partial pair or mixed forms throw. There is no bandwidth search. show reports resolved bandwidths, rule, degree, kernel, component selection and numerical tolerances.

For MultivariateFPCA, differentiation runs in node order and returns a MultivariateFPCADerivative. Shared or per-node keyword settings work as for marginal FPCA; component(d,j) retrieves the node result. Reconstruction, plotting, and mean data work nodewise, with shared or per-node grids. Both marginal and pooled fits support the two methods. Pooled FPC differentiates the shared basis and retains node scores. Pooled DPC uses each node's sample covariance and copied original training observations; its derivative components are node-specific.

Fixed-seed Fourier checks use simulate_kl with dense or sparse sampling. They check relative weighted derivative-function error and relative derivative-curve error below 0.12. Sparse checks supply the known mean, covariance and noise to isolate differentiation and CE reconstruction from covariance-smoothing bias. These are finite simulation checks, not general recovery guarantees.
