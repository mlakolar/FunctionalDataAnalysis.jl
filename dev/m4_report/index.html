Milestone 4: multivariate FPCA comparison

This report covers milestone 4 task 1: separate marginal FPCA fits and a shared pooled basis. Functional graphical estimators, cross-covariance surfaces, and Happ–Greven multivariate FPCA are later tasks.

The pooled route follows the partial-separability model of Zapata, Oh, and Petersen (2022), Biometrika 109(3), 665–681.

Reference and reproduction

The FunctionalGraphicalModels.jl reference is branch bsplinekit, commit 6f0eac3, provided in ~/projects/juliaPkg/fgm-ref-bsplinekit. Reference execution uses a temporary copy of that checkout so the original worktree is unchanged. test/reference/fgm_m4.jl is the committed generating script. The CSV headers record the reference branch, commit, Julia version, and relevant dependency versions. CI reads the committed CSVs and does not need to instantiate the reference package.

Generation ran on Julia 1.13.2 with FunctionalGraphicalModels.jl 0.1.0, BSplineKit 0.19.3, CovarianceSelection 0.1.0, ProximalBase 0.5.3, and ProximalSolvers 0.1.1. The original FGM worktree remained clean and had no Manifest.toml after generation.

The dense comparison aligns each reference eigenfunction's sign before comparing scores. Reference eigenvalues and per-node pooled score variances are multiplied by n/(n-1) because FDA uses sample covariance denominator n-1; the reference uses n. Scores themselves have the same normalization. The score array is ordered by subjects, nodes, then principal components.

Details resolved by the implementation

  • A numeric grid vector denotes one shared grid, even when its length equals the number of nodes. A vector of grids denotes per-node grids. Other vector-valued keyword containers must have one entry per node. Per-node nothing leaves that node's univariate default active.
  • Pooled maxK retains the task's dense-route bound min(g,n-1). The frozen FGM implementation allows min(g,p*(n-1)) because averaging node covariances can increase rank. FDA follows the requested dense cap; this restriction is explicit and does not imply that the pooled covariance has rank at most n-1.
  • Per-node pooled score variances preserve pooled component order. They are not sorted separately, since sorting would disconnect node scores from the common basis.
  • The common sign-reference curve is the equal-node average of the training mean curves. Near-zero overlap uses the existing largest-entry fallback, with the first entry breaking ties. This choice affects only signs, not the pooled covariance or score variances.
  • Pooled tuning accepts shared ncomponents, maxK, eigen_tol, and sign_tol, with method=:auto or :dense. Presmoothing, custom work grids, and PACE-specific options are rejected explicitly. The task did not define pooled presmoothing or a new pooled work-grid method.
  • score_array allocates an independent array. It copies node scores in the original node order and rejects unequal component counts.
  • Reconstruction preserves subject IDs only when every supplied node score matrix is the corresponding stored training matrix. Copied or new score matrices carry no inferred training IDs.
  • Pooled fits expose a shared basis and node score variances; they do not manufacture per-node FPCA objects. component therefore throws for pooled fits, as required by the API.
  • Marginal node fits retain their original numerical types. The vectors returned by multivariate numerical accessors use the promoted type across nodes; widening a node's arrays does not discard precision. With a common type, these arrays and basis objects reuse the stored univariate objects. Prediction uses the original node fits. Reconstruction promotes the fit, supplied score, and supplied grid types instead of narrowing new inputs.

Both are below 1e-8. The sparse comparison uses FGM's explicit Gaussian kernel, subject weighting, bandwidths, work grid, supplied noise variances, relative eigenvalue cutoff, and full retained covariance rank. These are compatibility settings, rather than FDA's unmodified defaults. See Comparison with FunctionalGraphicalModels.jl for every setting and the sign, cutoff, and singular-covariance differences.

Pooled PACE, masked pooled fitting, and mismatched pooled grids are unsupported and raise errors. The common-basis recovery check is a finite Monte Carlo diagnostic, not a general statistical guarantee. It uses 3,000 Gaussian curves per node, two nodes with the same weighted-orthonormal constant/linear basis, node score variances [4,1] and [2,0.5], and the fixed seed 20261024. Each absolute weighted correlation with the true basis must exceed 0.99; each pooled score variance must be within 6sqrt(2/(n-1)) times its target. These checks use inequalities rather than exact random-number output across Julia versions.
